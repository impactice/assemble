# 사칙연산 및 AX·BX·CX·DX 레지스터 출력 프로그램

두 정수를 입력받아 사칙연산 결과와 각 연산 직후의 레지스터 값을 출력하는 예제입니다.
온라인 실행용과 Visual Studio 실행용 소스 코드를 각각 제공합니다.

## 1. 파일 구성

| 파일 | 실행 환경 | 설명 |
|---|---|---|
| `main_mycompiler.asm` | myCompiler Assembly x86-64 / Linux NASM | 어셈블리 프로그램. Linux 시스템 호출로 입출력 |
| `main_visual_studio.cpp` | Windows Visual Studio / MSVC x86(Win32) | C++ 입출력 + `__asm` 인라인 어셈블리 연산 |
| `README.md` | Markdown 문서 | 실행 방법, 동작 원리, 테스트 방법 및 주의사항 |

두 프로그램은 **별개로 실행**합니다. 두 소스를 같은 실행 파일로 함께 빌드하지 마세요.

## 2. 공통 기능

- 0~65535 범위의 부호 없는 십진 정수 두 개 입력
- 덧셈·뺄셈·곱셈·정수 나눗셈
- 연산 결과는 10진수로 출력
- AX, BX, CX, DX는 네 자리 대문자 16진수로 출력
- 음수가 되는 뺄셈 결과 처리
- 덧셈 자리올림과 32비트 곱셈 결과 처리
- 정수 나눗셈의 몫과 나머지 출력
- 잘못된 입력 또는 입력 범위 초과 시 오류 메시지와 종료 코드 1
- 두 번째 숫자가 0이면 나눗셈을 생략하고 안내 메시지 출력

첫 두 숫자가 계산 대상이며 추가 입력은 사용하지 않습니다.
음수 입력, `+` 부호, 소수, 숫자가 아닌 문자는 허용하지 않습니다.
입력 숫자의 앞쪽 0은 허용합니다.

0으로 나누는 경우에도 덧셈·뺄셈·곱셈은 먼저 수행되며 프로그램 종료 코드는 0입니다.
나눗셈을 실행하지 않았으므로 나눗셈용 레지스터 결과는 출력하지 않습니다.

## 3. myCompiler에서 실행

실행 페이지: https://www.mycompiler.io/ko/new/asm-x86_64

1. Assembly x86-64 실행 페이지를 엽니다.
2. `main_mycompiler.asm`의 전체 내용을 편집기에 붙여 넣습니다.
3. 오른쪽 **입력** 탭에 숫자 두 개를 적습니다.
4. **실행** 버튼을 누릅니다.

입력 예:

```text
20
6
```

같은 줄에 `20 6`으로 입력해도 됩니다.
온라인 환경에서는 실행 중 출력 창에 입력하기보다 **입력 탭에 먼저 입력**하세요.

예상 출력:

```text
Enter two integers (0..65535).

[ADD] Result = 26
  AX = 001A  BX = 0006  CX = 0000  DX = 0000

[SUB] Result = 14
  AX = 000E  BX = 0006  CX = 0000  DX = 0000

[MUL] Result = 120
  AX = 0078  BX = 0006  CX = 0000  DX = 0000

[DIV] Quotient = 3
  AX = 0003  BX = 0006  CX = 0000  DX = 0002
  Remainder = 2
```

Linux x86-64에서 NASM과 GNU ld가 준비되어 있다면 다음 명령으로도 실행할 수 있습니다.

```bash
nasm -f elf64 main_mycompiler.asm -o calculator.o
ld calculator.o -o calculator
printf '20\n6\n' | ./calculator
```

## 4. Visual Studio에서 실행

### 필수 조건

- Windows용 Visual Studio
- **C++를 사용한 데스크톱 개발** 구성 요소
- MSVC 컴파일러
- **x86 또는 Win32 대상 플랫폼**

이 버전은 `.cpp` 파일에 `__asm` 블록을 넣는 **인라인 어셈블리 방식**입니다.
순수 `.asm` 파일만으로 구성된 프로그램이 아닙니다.
`Irvine32.inc`, `Irvine32.lib`, 별도 MASM 빌드 사용자 지정은 필요하지 않습니다.

### 설정 순서

1. Visual Studio에서 **C++ 콘솔 앱** 프로젝트를 만듭니다.
2. 자동 생성된 `.cpp` 파일의 내용을 `main_visual_studio.cpp`의 내용으로 교체합니다.
   - 또는 기존 파일을 프로젝트에서 제거하고 제공된 파일을 추가합니다.
   - `main()`이 있는 소스 파일은 프로젝트에 하나만 두세요.
3. 상단 빌드 플랫폼을 **x86**으로 바꿉니다.
   - 보이지 않으면 **빌드 → 구성 관리자**에서 플랫폼을 설정합니다.
   - C++ 프로젝트 플랫폼 이름이 **Win32**로 표시되어도 됩니다.
4. **Ctrl + F5**로 실행합니다.
5. 안내에 따라 정수 두 개를 입력합니다.

Visual Studio IDE 자체가 64비트여도 프로젝트 대상은 x86으로 설정해야 합니다.
이 소스의 `__asm`은 MSVC x64 대상으로 컴파일되지 않습니다.

기존 프로젝트에서 `pch.h` 관련 오류가 발생한다면:
- 프로젝트 속성 → C/C++ → 미리 컴파일된 헤더 → **미리 컴파일된 헤더 사용 안 함**으로 설정하거나,
- 프로젝트의 규칙에 맞게 소스 맨 위에 `#include "pch.h"`를 추가하세요.

### 명령줄 빌드(선택)

Visual Studio의 **x86 Native Tools Command Prompt**에서 실행합니다.

```bat
cl /nologo /EHsc /W4 main_visual_studio.cpp /Fe:calculator.exe
calculator.exe
```

일반 명령 프롬프트 또는 x64용 개발자 명령 프롬프트에서는 도구 설정/대상이 다를 수 있습니다.

### 출력 예

```text
First number (0..65535): 20
Second number (0..65535): 6

[ADD] Result = 26
  AX = 001A  BX = 0006  CX = 0000  DX = 0000

[SUB] Result = 14
  AX = 000E  BX = 0006  CX = 0000  DX = 0000

[MUL] Result = 120
  AX = 0078  BX = 0006  CX = 0000  DX = 0000

[DIV] Quotient = 3, Remainder = 2
  AX = 0003  BX = 0006  CX = 0000  DX = 0002
```

## 5. 동작 원리

### 레지스터 값은 연산 직후 저장

출력 함수나 시스템 호출도 레지스터를 사용합니다.
따라서 각 산술 연산 직후 AX·BX·CX·DX를 메모리에 먼저 저장하고,
화면에는 저장된 값을 출력합니다.

여기서 “연산 직후”는 덧셈의 `ADC`, 뺄셈의 `SBB`까지 포함한
결과 구성 단계가 완료된 시점입니다.

### AX, BX, CX, DX의 의미

| 연산 | AX | BX | CX | DX |
|---|---|---|---|---|
| 덧셈 | 합의 하위 16비트 | 두 번째 입력 | 0 | 합의 상위 16비트 |
| 뺄셈 | 차의 하위 16비트 | 두 번째 입력 | 0 | 음수이면 FFFF, 아니면 0000 |
| 곱셈 | 곱의 하위 16비트 | 두 번째 입력 | 0 | 곱의 상위 16비트 |
| 나눗셈 | 정수 몫 | 두 번째 입력 | 0 | 나머지 |

CX는 산술 연산에 사용하지 않아 매번 0으로 초기화합니다.
프로그램 실행 모드가 32비트/64비트여도 연산에는 명시적으로 16비트 레지스터를 사용합니다.

### 덧셈

```asm
add ax, bx
adc dx, 0
```

AX에서 발생한 자리올림을 DX에 반영하여 DX:AX에 결과를 보관합니다.
최대 합은 131070입니다.

### 뺄셈

```asm
sub ax, bx
sbb dx, 0
```

빌림이 발생하면 DX가 FFFF가 되어 음수 결과를 32비트 2의 보수로 표현합니다.
예: `3 - 5 = -2`일 때 DX:AX는 `FFFF:FFFE`입니다.

### 곱셈

```asm
mul bx
```

16비트 부호 없는 곱셈 결과를 DX:AX에 저장합니다.
최대 곱은 `65535 × 65535 = 4294836225`입니다.

### 나눗셈

```asm
xor dx, dx
div bx
```

DX:AX를 BX로 나누고 AX에 몫, DX에 나머지를 저장합니다.
BX가 0이면 실행하지 않습니다.

Visual Studio 버전의 C++ 부분은 입출력, 입력 검증,
저장된 결과의 워드 조합 및 음수 해석을 담당합니다.
사칙연산의 핵심 계산은 `__asm` 블록에서 수행합니다.

## 6. 확인용 테스트

| 첫 번째 수 | 두 번째 수 | 확인 사항 |
|---:|---:|---|
| 20 | 6 | 합 26, 차 14, 곱 120, 몫 3, 나머지 2 |
| 3 | 5 | 차 -2, 뺄셈 AX=FFFE 및 DX=FFFF |
| 65535 | 1 | 합 65536, 덧셈 AX=0000 및 DX=0001 |
| 65535 | 65535 | 곱 4294836225, 곱셈 DX=FFFE 및 AX=0001 |
| 20 | 0 | 나눗셈 생략 및 오류 안내 |
| 0 | 0 | 합·차·곱 0, 나눗셈 생략 |
| 65536 | 1 | 범위 초과 입력 거부 |
| abc | 1 | 숫자가 아닌 입력 거부 |

## 7. 검증 범위

이 파일 묶음을 생성한 환경에는 NASM 또는 링커가 없어 자동 실행 검증을 하지 못했습니다.

Visual Studio/MSVC 실행 환경은 파일 생성 환경에 없으므로,
Visual Studio 버전은 이곳에서 실제 빌드·실행 검증하지 못했습니다.
Windows의 MSVC x86 환경에서 위 테스트를 확인하세요.

## 8. 자주 발생하는 오류

| 증상 | 확인 및 해결 |
|---|---|
| `__asm` 관련 오류 | MSVC를 사용하고 있는지, 대상이 x86/Win32인지 확인 |
| NASM에서 `.MODEL`, `PROC`, `PTR` 오류 | 다른 환경용 코드를 넣은 상태. 온라인에서는 제공된 NASM 파일 사용 |
| Visual Studio에서 NASM 구문 오류 | 온라인용 `.asm` 대신 제공된 `.cpp` 파일 사용 |
| `main` 중복 정의 | 기본 소스와 제공 소스에 `main()`이 각각 있는지 확인 |
| `pch.h` 관련 오류 | 미리 컴파일된 헤더 설정을 조정 |
| 온라인 실행에서 입력 오류 | 실행 전에 입력 탭에 숫자 두 개 입력 |
| 0으로 나눌 때 레지스터가 표시되지 않음 | 예외 방지를 위해 나눗셈 명령 자체를 실행하지 않는 정상 동작 |

## 9. 제출 시 주의

과제에서 순수 MASM `.asm` 파일 또는 Irvine32 사용을 요구한다면,
제공된 Visual Studio 인라인 어셈블리 버전이 제출 형식에 맞는지 먼저 확인하세요.
이 묶음에는 실행 파일(.exe)이나 Visual Studio 솔루션(.sln)은 포함하지 않았습니다.
