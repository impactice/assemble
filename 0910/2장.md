# 2장

**1. In 32-bit mode, aside from the stack pointer (ESP), what other register points to variables on the stack?**

* **해석:** 32비트 모드에서 스택 포인터(ESP) 외에 스택의 변수를 가리키는 레지스터는 무엇인가?
* **정답:** `EBP` (Extended Base Pointer)
* **설명:** EBP는 스택 프레임의 기준 주소를 저장하여 지역 변수나 매개변수에 접근할 때 사용됩니다.

**2. Name at least four CPU status flags.**

* **해석:** 최소 4개의 CPU 상태 플래그 이름을 쓰시오.
* **정답:** `Carry Flag (CF)`, `Zero Flag (ZF)`, `Sign Flag (SF)`, `Overflow Flag (OF)`
* **설명:** 그 외에도 Parity Flag (PF), Auxiliary Carry Flag (AF) 등이 있습니다.

**3. Which flag is set when the result of an unsigned arithmetic operation is too large to fit into the destination?**

* **해석:** 부호 없는(unsigned) 산술 연산의 결과가 너무 커서 대상(destination)에 들어갈 수 없을 때 설정되는 플래그는 무엇인가?
* **정답:** `Carry Flag (CF)`

**4. Which flag is set when the result of a signed arithmetic operation is either too large or too small to fit into the destination?**

* **해석:** 부호 있는(signed) 산술 연산의 결과가 너무 크거나 작아서 대상에 들어갈 수 없을 때 설정되는 플래그는 무엇인가?
* **정답:** `Overflow Flag (OF)`

**5. (True/False): When a register operand size is 32 bits and the REX prefix is used, the R8D register is available for programs to use.**

* **해석:** (참/거짓): 레지스터 피연산자 크기가 32비트이고 REX 접두사가 사용될 때, 프로그램에서 R8D 레지스터를 사용할 수 있다.
* **정답:** `True`
* **설명:** 64비트 환경에서 R8\~R15가 추가되며, R8의 32비트 하위 레지스터가 R8D입니다. 이를 사용하려면 REX 접두사가 필요합니다.

**6. Which flag is set when an arithmetic or logical operation generates a negative result?**

* **해석:** 산술 또는 논리 연산이 음수 결과를 생성할 때 설정되는 플래그는 무엇인가?
* **정답:** `Sign Flag (SF)`

**7. Which part of the CPU performs floating-point arithmetic?**

* **해석:** CPU의 어느 부분이 부동소수점 산술 연산을 수행하는가?
* **정답:** `FPU` (Floating-Point Unit) 또는 코프로세서(Coprocessor)

**8. On a 32-bit processor, how many bits are contained in each floating-point data register?**

* **해석:** 32비트 프로세서에서 각 부동소수점 데이터 레지스터에는 몇 비트가 포함되어 있는가?
* **정답:** `80 bits`
* **설명:** x87 FPU 레지스터(ST(0)\~ST(7))는 정밀도 손실 방지를 위해 내부적으로 80비트 확장 정밀도 형식을 사용합니다.

**9. (True/False): The x86-64 instruction set is backward-compatible with the x86 instruction set.**

* **해석:** (참/거짓): x86-64 명령어 세트는 x86 명령어 세트와 하위 호환된다.
* **정답:** `True`

**10. (True/False): In current 64-bit chip implementations, all 64 bits are used for addressing.**

* **해석:** (참/거짓): 현재의 64비트 칩 구현에서 64비트 전체가 주소 지정에 사용된다.
* **정답:** `False`
* **설명:** 현재 구현된 x86-64 프로세서들은 가상 주소 공간에 전체 64비트를 사용하지 않으며, 주로 48비트 또는 57비트를 사용합니다.

**11. (True/False): The Itanium instruction set is completely different from the x86 instruction set.**

* **해석:** (참/거짓): 아이테니엄(Itanium) 명령어 세트는 x86 명령어 세트와 완전히 다르다.
* **정답:** `True`
* **설명:** Itanium(IA-64)은 EPIC 아키텍처 기반으로 x86 아키텍처와 전혀 다릅니다.

**12. (True/False): Static RAM is usually less expensive than dynamic RAM.**

* **해석:** (참/거짓): 일반적으로 정적 RAM(SRAM)은 동적 RAM(DRAM)보다 저렴하다.
* **정답:** `False`
* **설명:** SRAM은 DRAM보다 속도가 빠르지만 구조가 복잡하여 훨씬 비쌉니다. (주로 캐시 메모리로 사용됨)

**13. (True/False): The 64-bit RDI register is available when the REX prefix is used.**

* **해석:** (참/거짓): REX 접두사를 사용하면 64비트 RDI 레지스터를 사용할 수 있다.
* **정답:** `True`
* **설명:** 64비트 명령어 인코딩에서 64비트 크기의 피연산자(RDI 포함)를 명시적으로 다루기 위해서는 REX 접두사(REX.W)가 필요합니다.

**14. (True/False): In native 64-bit mode, you can use 16-bit real mode, but not the virtual-8086 mode.**

* **해석:** (참/거짓): 네이티브 64비트 모드에서는 16비트 리얼 모드를 사용할 수 있지만, 가상-8086 모드는 사용할 수 없다.
* **정답:** `False`
* **설명:** 네이티브 64비트 모드(Long Mode)에서는 16비트 리얼 모드와 가상-8086 모드 둘 다 사용할 수 없습니다.

**15. (True/False): The x86-64 processors have 4 more general-purpose registers than the x86 processors.**

* **해석:** (참/거짓): x86-64 프로세서는 x86 프로세서보다 범용 레지스터가 4개 더 많다.
* **정답:** `False`
* **설명:** 8개가 더 많습니다. (R8\~R15가 추가됨)

**16. (True/False): The 64-bit version of Microsoft Windows does not support virtual-8086 mode.**

* **해석:** (참/거짓): 마이크로소프트 윈도우 64비트 버전은 가상-8086 모드를 지원하지 않는다.
* **정답:** `True`
* **설명:** 이로 인해 64비트 윈도우에서는 16비트 DOS/Windows 프로그램을 네이티브로 실행할 수 없습니다.

**17. (True/False): DRAM can only be erased using ultraviolet light.**

* **해석:** (참/거짓): DRAM은 자외선을 사용해서만 지울 수 있다.
* **정답:** `False`
* **설명:** 자외선으로 지우는 메모리는 EPROM(Erasable Programmable ROM)입니다. DRAM은 전기적으로 데이터를 갱신합니다.

**18. (True/False): In 64-bit mode, you can use up to eight floating-point registers.**

* **해석:** (참/거짓): 64비트 모드에서는 최대 8개의 부동소수점 레지스터를 사용할 수 있다.
* **정답:** `False`
* **설명:** 레거시 x87 레지스터(8개) 외에도 16개의 XMM/YMM 레지스터를 활용하여 부동소수점 연산을 수행할 수 있습니다. 8개로 제한되지 않습니다.

**19. (True/False): A bus is a plastic cable that is attached to the motherboard at both ends, but does not sit directly on the motherboard.**

* **해석:** (참/거짓): 버스(Bus)는 양 끝이 마더보드에 연결되어 있지만 마더보드 위에 직접 위치하지 않는 플라스틱 케이블이다.
* **정답:** `False`
* **설명:** 버스는 마더보드 상의 전기적 회로(트레이스) 집합을 의미합니다. (일부 리본 케이블 버스도 있으나 전체 정의로 부합하지 않음)

**20. (True/False): CMOS RAM is the same as static RAM, meaning that it holds its value without any extra power or refresh cycles.**

* **해석:** (참/거짓): CMOS RAM은 정적 RAM과 동일하며, 추가 전력이나 새로고침 주기 없이도 그 값을 유지한다는 의미이다.
* **정답:** `False`
* **설명:** CMOS RAM은 비휘발성이 아니며, 전원이 꺼진 상태에서도 데이터를 유지하려면 메인보드의 소형 배터리(CR2032 등)로부터 전력을 공급받아야 합니다.

**21. (True/False): PCI connectors are used for graphics cards and sound cards.**

* **해석:** (참/거짓): PCI 커넥터는 그래픽 카드와 사운드 카드에 사용된다.
* **정답:** `True`
* **설명:** 현대에는 PCIe(PCI Express)를 주로 사용하지만, 넓은 의미에서 호환/발전된 형태이므로 정답으로 간주됩니다.

**22. (True/False): The 8259A is a controller that handles external interrupts from hardware devices.**

* **해석:** (참/거짓): 8259A는 하드웨어 장치의 외부 인터럽트를 처리하는 컨트롤러이다.
* **정답:** `True`
* **설명:** PIC (Programmable Interrupt Controller)입니다.

**23. (True/False): The acronym PCI stands for programmable component interface.**

* **해석:** (참/거짓): PCI라는 약어는 프로그래머블 컴포넌트 인터페이스를 의미한다.
* **정답:** `False`
* **설명:** Peripheral Component Interconnect 의 약자입니다.

**24. (True/False): VRAM stands for virtual random access memory.**

* **해석:** (참/거짓): VRAM은 가상 랜덤 액세스 메모리를 의미한다.
* **정답:** `False`
* **설명:** Video Random Access Memory 의 약자입니다.

**25. At which level(s) can an assembly language program manipulate input/output?**

* **해석:** 어셈블리어 프로그램은 어느 수준(레벨)에서 입출력을 조작할 수 있는가?
* **정답:** 하드웨어 레벨(I/O 포트 직접 제어), BIOS 레벨(BIOS 인터럽트 호출), OS 레벨(OS API 및 시스템 콜 호출)의 세 가지 수준 모두에서 조작 가능합니다.

**26. Why do game programs often send their sound output directly to the sound card’s hardware ports?**

* **해석:** 게임 프로그램이 사운드 출력을 사운드 카드의 하드웨어 포트로 직접 보내는 경우가 많은 이유는 무엇인가?
* **정답:** 운영체제를 거치면서 발생하는 오버헤드를 없애고 **지연 시간(Latency)을 최소화하여 성능과 실시간성을 극대화**하기 위해서입니다. (특히 과거 DOS 시절에 필수적인 기법이었습니다.)
