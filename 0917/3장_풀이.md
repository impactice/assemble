# 3장 어셈블리 언어 기초 — 연습문제 풀이

> 교재: Kip Irvine, *Assembly Language for x86 Processors*, 7th ed.
> 각 문제는 한국어로 요약했고, 원문 핵심 표현(영문)을 짧게 함께 적었습니다. 전체 원문은 교재 3.9절, 3.10절을 참고하세요.

---

## 3.9.1 단답형 (Short Answer)

### 1. 서로 다른 명령어 니모닉 세 개를 예로 드시오
*원문 핵심어: "three different instruction mnemonics"*

MOV(데이터 복사), ADD(덧셈), SUB(뺄셈)입니다. JMP, CALL도 정답이 됩니다.

### 2. 호출 규약이란 무엇이고, 어셈블리 선언에서 어떻게 쓰이는가
*원문 핵심어: "calling convention"*

프로시저를 호출할 때 인자를 어떤 순서로 전달하고, 호출이 끝난 뒤 누가 스택을 정리하는지 등을 정한 규칙입니다. `.model flat,stdcall`에서 `stdcall`이 호출 규약을 지정합니다. 32비트 Windows API 함수는 stdcall 규약으로 호출해야 합니다.

### 3. 프로그램에서 스택 공간은 어떻게 확보하는가
*원문 핵심어: "reserve space for the stack"*

`.STACK` 지시어를 씁니다. 예를 들어 `.stack 4096`은 4096바이트를 확보합니다.

### 4. "assembler language"라는 용어가 정확하지 않은 이유
*원문 핵심어: "assembler language"*

어셈블러(assembler)는 소스를 번역하는 프로그램의 이름입니다. 언어의 올바른 이름은 어셈블리 언어(assembly language)입니다.

### 5. 빅엔디언과 리틀엔디언의 차이, 용어의 유래
*원문 핵심어: "big endian and little endian"*

- 빅엔디언: 최상위 바이트를 가장 낮은 주소에 저장합니다.
- 리틀엔디언: 최하위 바이트를 가장 낮은 주소에 저장합니다. x86이 이 방식을 씁니다.
- 유래: 『걸리버 여행기』에서 달걀을 큰 쪽부터 깨느냐 작은 쪽부터 깨느냐로 싸우는 이야기에서 왔습니다. 1980년 대니 코헨이 바이트 순서 논쟁에 이 비유를 처음 썼습니다.

### 6. 정수 리터럴 대신 기호 상수를 쓰는 이유
*원문 핵심어: "symbolic constant rather than an integer literal"*

값의 의미가 드러나 코드를 읽기 쉽습니다. 값이 바뀔 때 정의 한 곳만 고치면 되므로 유지보수도 쉽습니다. 예를 들어 `mov al,27`보다 `mov al,Esc_key`가 이해하기 쉽습니다.

### 7. 소스 파일과 리스팅 파일의 차이
*원문 핵심어: "source file ... listing file"*

- 소스 파일: 프로그래머가 편집기로 작성한 `.asm` 파일입니다.
- 리스팅 파일: 어셈블러가 생성한 파일로, 소스 코드에 줄 번호, 주소(오프셋), 기계어 바이트, 심볼 테이블이 덧붙어 있습니다.

### 8. 데이터 레이블과 코드 레이블의 차이
*원문 핵심어: "data labels and code labels"*

- 데이터 레이블은 변수의 위치를 나타내며 콜론 없이 씁니다. 예: `count DWORD 100`
- 코드 레이블은 코드 영역에 있고 콜론(`:`)으로 끝나며, 점프나 루프의 목적지로 쓰입니다. 예: `L1:`

### 9. (참/거짓) 식별자는 숫자로 시작할 수 없다
**참.** 첫 글자는 영문자, `_`, `@`, `?`, `$` 중 하나여야 합니다.

### 10. (참/거짓) 16진수 리터럴을 0x3A로 쓸 수 있다
**거짓.** MASM에서는 `3Ah`로 씁니다. `0x` 표기는 C 언어 방식입니다.

### 11. (참/거짓) 지시어는 실행 시간에 동작한다
**거짓.** 지시어는 어셈블할 때 어셈블러가 처리합니다. 실행 시간에 동작하는 것은 명령어입니다.

### 12. (참/거짓) 지시어는 대문자와 소문자를 섞어 써도 된다
**참.** `.data`, `.DATA`, `.Data`는 모두 같습니다.

### 13. 명령어의 네 가지 기본 구성 요소
*원문 핵심어: "four basic parts of an assembly language instruction"*

레이블(선택), 니모닉(필수), 피연산자(대개 필요), 주석(선택)입니다.

### 14. (참/거짓) MOV는 명령어 니모닉의 예이다
**참.**

### 15. (참/거짓) 코드 레이블 뒤에는 콜론이 붙지만 데이터 레이블에는 붙지 않는다
**참.**

### 16. 블록 주석의 예
*원문 핵심어: "block comment"*

```asm
COMMENT !
  이 줄은 주석입니다.
  이 줄도 주석입니다.
!
```

### 17. 변수에 접근할 때 숫자 주소를 쓰면 안 되는 이유
*원문 핵심어: "numeric addresses"*

데이터를 추가하거나 삭제하면 변수의 주소가 바뀝니다. 기호 이름을 쓰면 어셈블러가 주소를 자동으로 계산해 주고, 코드도 읽기 쉬워집니다.

### 18. ExitProcess에 전달해야 하는 인자의 종류
32비트 정수(DWORD) 종료 코드 `dwExitCode`입니다. 0은 정상 종료를 뜻합니다.

### 19. 프로시저를 끝내는 지시어
**ENDP**

### 20. 32비트 모드에서 END 지시어 뒤 식별자의 역할
프로그램 진입점, 즉 실행이 시작되는 위치를 지정합니다. 예: `END main`

### 21. PROTO 지시어의 목적
프로시저의 이름과 매개변수를 미리 선언하는 프로토타입입니다. 외부 함수를 호출할 수 있게 하고, INVOKE로 호출할 때 어셈블러가 인자를 검사할 수 있게 합니다.

### 22. (참/거짓) 목적 파일은 링커가 만든다
**거짓.** 목적 파일은 어셈블러가 만들고, 링커는 실행 파일을 만듭니다.

### 23. (참/거짓) 리스팅 파일은 어셈블러가 만든다
**참.**

### 24. (참/거짓) 링크 라이브러리는 실행 파일을 만들기 직전에 프로그램에 추가된다
**참.** 링크 단계에서 링커가 라이브러리에서 필요한 프로시저를 복사해 목적 파일과 합친 뒤 실행 파일을 만듭니다.

### 25~29. 알맞은 데이터 지시어

| 문제 | 조건 | 답 |
|---|---|---|
| 25 | 32비트 부호 있는 정수 | `SDWORD` |
| 26 | 16비트 부호 있는 정수 | `SWORD` |
| 27 | 64비트 부호 없는 정수 | `QWORD` |
| 28 | 8비트 부호 있는 정수 | `SBYTE` |
| 29 | 10바이트 packed BCD | `TBYTE` |

## 3.9.2 알고리즘 연습 (Algorithm Workbench)

### 1. 정수 25를 10진, 2진, 8진, 16진으로 나타내는 기호 상수
*원문 핵심어: "integer 25 in decimal, binary, octal, and hexadecimal"*

```asm
DEC_25 = 25
BIN_25 = 11001b
OCT_25 = 31o
HEX_25 = 19h
```

### 2. 코드 세그먼트와 데이터 세그먼트를 여러 개 둘 수 있는가
가능합니다. `.code`와 `.data`를 여러 번 써도 어셈블러가 같은 종류끼리 하나의 세그먼트로 합칩니다. 다만 코드가 읽기 어려워집니다.

### 3. 더블워드를 빅엔디언 순서로 저장하는 정의
DWORD로 정의하면 리틀엔디언으로 저장되므로, BYTE로 한 바이트씩 직접 나열합니다.

```asm
bigEndianVal BYTE 12h, 34h, 56h, 78h   ; 12345678h
```

### 4. DWORD 변수에 음수를 대입할 수 있는가
가능합니다. `val DWORD -1`은 `FFFFFFFFh`로 저장됩니다. 어셈블러는 크기만 검사하고 부호 여부는 검사하지 않는다는 뜻입니다.

### 5. `add eax,5`와 `add edx,5`의 기계어 비교
```
83 C0 05    add eax,5
83 C2 05    add edx,5
```
두 번째 바이트(ModR/M)만 다르며, 이 바이트가 대상 레지스터를 나타냅니다(C0은 EAX, C2는 EDX). `83`은 연산 코드이고 `05`는 즉시값입니다.

### 6. 456789ABh를 리틀엔디언 순서로 나열
`AB 89 67 45`

### 7. 부호 없는 더블워드 120개짜리 초기화되지 않은 배열
```asm
arr DWORD 120 DUP(?)
```

### 8. 알파벳 앞 5글자로 초기화한 바이트 배열
```asm
letters BYTE 'A','B','C','D','E'      ; 또는 BYTE "ABCDE"
```

### 9. 32비트 부호 있는 변수를 가장 작은 음수로 초기화
```asm
minVal SDWORD -2147483648             ; -2^31
```

### 10. 초기값 3개를 가진 부호 없는 16비트 변수 wArray
```asm
wArray WORD 10, 20, 30
```

### 11. 좋아하는 색 이름을 담은 null 종료 문자열
```asm
favColor BYTE "blue",0
```

### 12. 부호 있는 더블워드 50개짜리 초기화되지 않은 배열 dArray
```asm
dArray SDWORD 50 DUP(?)
```

### 13. "TEST"를 500번 반복한 문자열
```asm
testStr BYTE 500 DUP("TEST")          ; 총 2000바이트
```

### 14. 0으로 초기화한 부호 없는 바이트 20개짜리 배열 bArray
```asm
bArray BYTE 20 DUP(0)
```

### 15. `val1 DWORD 87654321h`의 메모리 바이트 순서(낮은 주소부터)
`21 43 65 87`

## 3.10 프로그래밍 과제 (Programming Exercises)

### 1. 정수 식 계산 (Integer Expression Calculation) ★
*원문 핵심어: "A = (A + B) − (C + D)"*

**문제 요약:** AddTwo 프로그램을 참고해 레지스터로 A = (A + B) − (C + D)를 계산하시오. EAX, EBX, ECX, EDX에 정수 값을 넣어 사용합니다.

**풀이:** EAX를 A, EBX를 B, ECX를 C, EDX를 D로 사용합니다. 먼저 A+B와 C+D를 각각 구한 뒤 뺍니다.

```asm
; IntExpr.asm - A = (A + B) - (C + D)
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.code
main PROC
    mov eax,10          ; A = 10
    mov ebx,20          ; B = 20
    mov ecx,5           ; C = 5
    mov edx,3           ; D = 3

    add eax,ebx         ; EAX = A + B = 30
    add ecx,edx         ; ECX = C + D = 8
    sub eax,ecx         ; EAX = 30 - 8 = 22 (16h)

    INVOKE ExitProcess,0
main ENDP
END main
```
디버거에서 `sub` 실행 후 EAX가 `00000016h`(22)인지 확인합니다.

### 2. 기호 정수 상수 (Symbolic Integer Constants) ★
*원문 핵심어: "all seven days of the week"*

**문제 요약:** 요일 7개에 대한 기호 상수를 정의하고, 그 상수들을 초기값으로 쓰는 배열 변수를 만드시오.

**풀이:** 등호(`=`) 지시어로 상수를 정의합니다. 상수는 메모리를 차지하지 않고, 배열에는 실제 값이 들어갑니다.

```asm
; DaysOfWeek.asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

Sunday    = 0
Monday    = 1
Tuesday   = 2
Wednesday = 3
Thursday  = 4
Friday    = 5
Saturday  = 6

.data
weekDays BYTE Sunday, Monday, Tuesday, Wednesday, Thursday, Friday, Saturday

.code
main PROC
    mov al,weekDays          ; AL = 0 (Sunday)
    mov al,[weekDays+5]      ; AL = 5 (Friday)
    INVOKE ExitProcess,0
main ENDP
END main
```

### 3. 데이터 정의 (Data Definitions) ★★
*원문 핵심어: "each data type listed in Table 3-2"*

**문제 요약:** 표 3-2의 모든 내장 데이터 타입으로 변수를 하나씩 정의하고, 타입에 맞는 값으로 초기화하시오.

**풀이:**

```asm
; DataDefs.asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
vByte    BYTE    255                 ; 8비트 부호 없는 정수 (최댓값)
vSByte   SBYTE   -128                ; 8비트 부호 있는 정수 (최솟값)
vWord    WORD    65535               ; 16비트 부호 없는 정수
vSWord   SWORD   -32768              ; 16비트 부호 있는 정수
vDword   DWORD   12345678h           ; 32비트 부호 없는 정수
vSDword  SDWORD  -2147483648         ; 32비트 부호 있는 정수
vFword   FWORD   123456789ABCh       ; 48비트 정수 (far 포인터)
vQword   QWORD   1234567812345678h   ; 64비트 정수
vTbyte   TBYTE   1234h               ; 80비트 packed BCD (+1234)
vReal4   REAL4   -1.5                ; 32비트 단정밀도 실수
vReal8   REAL8   3.14159265358979    ; 64비트 배정밀도 실수
vReal10  REAL10  4.6E+4096           ; 80비트 확장 정밀도 실수

.code
main PROC
    INVOKE ExitProcess,0
main ENDP
END main
```
참고: TBYTE의 BCD 초기값은 16진수로 써야 합니다(3.4.8절). `TBYTE -1234`처럼 10진수로 쓰면 BCD가 아닌 이진 정수로 저장됩니다.

### 4. 기호 텍스트 상수 (Symbolic Text Constants) ★
*원문 핵심어: "symbolic names for several string literals"*

**문제 요약:** 여러 문자열 리터럴에 기호 이름을 붙이고, 각 이름을 변수 정의에 사용하시오.

**풀이:** `TEXTEQU`(또는 `EQU <...>`)로 텍스트 매크로를 만들면, 어셈블러가 이름을 그 텍스트로 치환합니다.

```asm
; TextConst.asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

greeting   TEXTEQU <"Hello, Assembly!",0>
promptMsg  TEXTEQU <"Enter a number: ",0>
errorMsg   EQU     <"Invalid input.",0>
byeMsg     TEXTEQU <"Goodbye!",0dh,0ah,0>

.data
msg1 BYTE greeting
msg2 BYTE promptMsg
msg3 BYTE errorMsg
msg4 BYTE byeMsg

.code
main PROC
    INVOKE ExitProcess,0
main ENDP
END main
```

### 5. AddTwoSum의 리스팅 파일 (Listing File for AddTwoSum) ★★★★
*원문 핵심어: "description of the machine code bytes"*

**문제 요약:** AddTwoSum 프로그램의 리스팅 파일을 생성하고, 각 명령어에 대해 생성된 기계어 바이트를 설명하시오.

**리스팅 파일 생성 방법(Visual Studio):** Project → Properties → Microsoft Macro Assembler → Listing File에서 *Generate Preprocessed Source Listing*과 *List All Available Information*을 Yes로 설정합니다.

**예상 결과와 해설:**

```
00000000 B8 00000005     mov eax,5
00000005 83 C0 06        add eax,6
00000008 A3 00000000 R   mov sum,eax
                         INVOKE ExitProcess,0
0000000D 6A 00           push +000000000h
0000000F E8 00000000 E   call ExitProcess
```

| 명령어 | 기계어 | 설명 |
|---|---|---|
| `mov eax,5` | `B8 00000005` | `B8`은 "32비트 즉시값을 EAX로 이동"하는 연산 코드입니다(B8 + 레지스터 번호 0). 뒤따르는 4바이트가 즉시값 5이며, 메모리에는 `05 00 00 00`으로 저장됩니다. 총 5바이트입니다. |
| `add eax,6` | `83 C0 06` | `83`은 "8비트 부호 확장 즉시값을 r/m32에 연산"하는 연산 코드이고, `C0`은 ModR/M 바이트(연산은 ADD, 대상은 EAX)입니다. `06`은 즉시값입니다. 작은 수라 1바이트로 인코딩되어 총 3바이트입니다. |
| `mov sum,eax` | `A3 00000000 R` | `A3`은 "EAX를 메모리 주소로 이동"하는 전용 단축 연산 코드입니다. 뒤의 4바이트는 `sum`의 주소(데이터 세그먼트 내 오프셋 0)입니다. `R`은 재배치(relocatable) 표시로, 로드할 때 실제 주소로 바뀝니다. |
| `push 0` | `6A 00` | INVOKE가 자동으로 만든 명령입니다. `6A`는 "8비트 즉시값 push" 연산 코드이고, `00`이 종료 코드 0입니다. |
| `call ExitProcess` | `E8 00000000 E` | `E8`은 상대 주소 CALL 연산 코드입니다. `E`는 외부(external) 심볼이라는 뜻으로, 주소를 링커가 채웁니다. |

오프셋이 0 → 5 → 8 → 0D → 0F로 증가하는 것은 앞 명령어의 바이트 수(5, 3, 5, 2)만큼 더해졌기 때문입니다.

### 6. AddVariables 프로그램 (64비트 변환) ★★★
*원문 핵심어: "so it uses 64-bit variables"*

**문제 요약:** AddVariables 프로그램이 64비트 변수를 사용하도록 수정하고, 어셈블러가 낸 구문 오류와 해결 과정을 설명하시오.

**수정 과정에서 만나는 오류와 해결:**

1. **변수만 QWORD로 바꾸고 EAX를 그대로 둔 경우** → `instruction operands must be the same size` 오류가 납니다. 레지스터를 RAX로 바꿔 해결합니다.
2. **`.386`, `.model flat,stdcall`, `.stack`** → 64비트 어셈블러(ml64)는 이 지시어를 지원하지 않아 오류가 납니다. 세 줄을 삭제합니다.
3. **`ExitProcess PROTO, dwExitCode:DWORD`** → 64비트 PROTO는 매개변수를 적지 않습니다. `ExitProcess PROTO`로 바꿉니다.
4. **`INVOKE ExitProcess,0`** → 64비트 MASM은 INVOKE를 지원하지 않습니다. `mov ecx,0` / `call ExitProcess`로 바꿉니다.
5. **`END main`** → 64비트에서는 END 뒤에 진입점을 적지 않습니다(진입점은 링커 설정에서 지정). `END`만 씁니다.

**완성 코드:**

```asm
; AddVariables_64.asm
ExitProcess PROTO

.data
firstval  QWORD 20002000h
secondval QWORD 11111111h
thirdval  QWORD 22222222h
sum       QWORD 0

.code
main PROC
    mov rax,firstval        ; RAX = 20002000h
    add rax,secondval       ; RAX = 31113111h
    add rax,thirdval        ; RAX = 53335333h
    mov sum,rax             ; sum = 53335333h

    mov ecx,0               ; 종료 코드 (첫 번째 인자는 RCX)
    call ExitProcess
main ENDP
END
```
결과는 32비트 버전과 같은 `53335333h`입니다. 64비트 레지스터를 쓰므로 필요하면 더 큰 값(예: `1000000000000h`)도 더할 수 있습니다.
