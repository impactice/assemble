# 5장 프로시저 — 연습문제 풀이

> Kip Irvine, *Assembly Language for x86 Processors* 7판, 5.8절~5.9절
> 문제는 한국어로 요약했습니다. 원문은 교재 183~188쪽을 함께 보세요.

---

## 5.8.1 단답형 (Short Answer)

### 1. 32비트 범용 레지스터 전부를 스택에 넣는 명령어는?

**PUSHAD**

EAX, ECX, EDX, EBX, ESP, EBP, ESI, EDI 순서로 8개를 넣습니다. 32바이트를 씁니다.

> 16비트용은 PUSHA 이고, 16비트 모드에서만 써야 합니다.

---

### 2. 32비트 EFLAGS 레지스터를 스택에 넣는 명령어는?

**PUSHFD**

> 16비트 FLAGS용은 PUSHF 입니다.

---

### 3. 스택의 값을 EFLAGS 레지스터로 꺼내는 명령어는?

**POPFD**

---

### 4. (도전) 다른 어셈블러(NASM)는 PUSH에 레지스터를 여러 개 나열할 수 있다. 이 방식이 MASM의 PUSHAD보다 나은 점은?

**필요한 레지스터만 골라 저장할 수 있어 더 효율적입니다.**

PUSHAD는 쓰지 않는 레지스터까지 8개 전부 저장하므로 32바이트를 소비하고 실행 시간도 더 듭니다. 세 개만 바꾸는 프로시저라면 12바이트만 쓰면 됩니다.

또 PUSHAD는 **EAX까지 저장·복원**하므로, 반환값을 EAX에 담는 프로시저에서는 쓸 수 없습니다. 레지스터를 지정할 수 있으면 EAX만 빼고 저장하면 됩니다.

---

### 5. (도전) PUSH 명령어가 없다고 가정하고, `push eax` 와 같은 일을 하는 두 명령어를 쓰시오.

```asm
sub esp,4               ; 스택 포인터를 4 감소
mov [esp],eax           ; 그 자리에 EAX 저장
```

> PUSH의 동작 순서가 **감소 먼저, 저장 나중**임을 그대로 옮긴 것입니다.
> 참고로 `pop eax` 는 반대 순서입니다.
> ```asm
> mov eax,[esp]
> add esp,4
> ```

---

### 6. (참/거짓) RET 명령어는 스택의 맨 위 값을 명령어 포인터로 꺼낸다.

**참.**

RET은 스택에서 복귀 주소를 POP 해서 EIP(64비트는 RIP)에 넣습니다.

---

### 7. (참/거짓) MASM은 NESTED 연산자를 쓰지 않으면 중첩 프로시저 호출을 허용하지 않는다.

**거짓.**

중첩 호출은 아무런 선언 없이 가능합니다. 스택이 LIFO 구조라 복귀 주소가 차례로 쌓였다가 역순으로 꺼내지기 때문입니다. NESTED 같은 연산자는 존재하지 않습니다.

---

### 8. (참/거짓) 보호 모드에서 각 프로시저 호출은 최소 4바이트의 스택 공간을 쓴다.

**참.**

32비트 보호 모드에서 복귀 주소가 4바이트이기 때문입니다. 여기에 저장하는 레지스터나 인자가 있으면 더 늘어납니다.

---

### 9. (참/거짓) 프로시저에 32비트 인자를 전달할 때 ESI와 EDI는 쓸 수 없다.

**거짓.**

ESI와 EDI도 범용 레지스터이므로 인자 전달에 쓸 수 있습니다. 실제로 ArraySum 프로시저는 ESI로 배열 주소를 받습니다.

---

### 10. (참/거짓) ArraySum 프로시저는 더블워드 배열의 포인터를 받는다.

**참.**

ESI에 배열의 오프셋을, ECX에 원소 개수를 받습니다.

---

### 11. (참/거짓) USES 연산자로 프로시저 안에서 수정되는 레지스터를 모두 나열할 수 있다.

**참.**

어셈블러가 PUSH와 POP을 자동 생성합니다.

---

### 12. (참/거짓) USES는 PUSH만 생성하므로 POP은 직접 써야 한다.

**거짓.**

PUSH와 POP을 **모두** 생성합니다. 프로시저 시작에 PUSH를, RET 직전에 역순으로 POP을 넣습니다.

---

### 13. (참/거짓) USES 지시어의 레지스터 목록은 쉼표로 구분해야 한다.

**거짓.**

**공백**으로 구분합니다.

```asm
MySub PROC USES eax ebx ecx     ; 쉼표 없음
```

---

### 14. ArraySum 프로시저가 16비트 워드 배열을 다루도록 바꾸려면 어느 문장을 고쳐야 하는가?

바꿔야 할 곳은 **두 군데**입니다.

```asm
ArraySum PROC USES esi ecx
    mov eax,0
    cmp ecx,0
    je  L2
L1:
    add ax,[esi]            ; ← EAX → AX (16비트 누적)
    add esi,TYPE WORD       ; ← 4 → 2 (워드는 2바이트)
    loop L1
L2: ret
ArraySum ENDP
```

**수정 내용**
1. `add eax,[esi]` → `add ax,[esi]` — 피연산자 크기를 맞춰야 합니다. 메모리가 16비트인데 EAX(32비트)와 더할 수 없습니다.
2. `add esi,4` → `add esi,2` — 워드는 2바이트씩 이동합니다. `TYPE` 연산자를 쓰면 더 안전합니다.

> 합계가 16비트를 넘길 수 있다면 `movzx eax,WORD PTR [esi]` 로 확장한 뒤 EAX에 더하는 편이 낫습니다.

---

### 15. 실행 후 EAX 값은?

```asm
push 5
push 6
pop eax
pop eax
```

**EAX = 5**

| 단계 | 스택 (위 → 아래) | EAX |
|---|---|---|
| `push 5` | 5 | — |
| `push 6` | 6, 5 | — |
| `pop eax` | 5 | 6 |
| `pop eax` | (비어 있음) | **5** |

LIFO이므로 6이 먼저 나오고, 두 번째 POP에서 5가 EAX를 덮어씁니다.

### 16. 다음 코드 실행 시 어떤 일이 일어나는가?

```asm
 1: main PROC
 2:     push 10
 3:     push 20
 4:     call Ex2Sub
 5:     pop eax
 6:     INVOKE ExitProcess,0
 7: main ENDP
 8:
 9: Ex2Sub PROC
10:     pop eax
11:     ret
12: Ex2Sub ENDP
```

**정답: 11번 줄에서 런타임 오류가 발생합니다.**

스택 상태를 따라가 봅니다.

| 단계 | 스택 (위 → 아래) |
|---|---|
| `push 10` | 10 |
| `push 20` | 20, 10 |
| `call Ex2Sub` | **복귀주소**, 20, 10 |
| 10번 줄 `pop eax` | 20, 10 (EAX = 복귀주소) |
| 11번 줄 `ret` | 10 → **EIP = 20** |

10번 줄의 POP이 **복귀 주소를 꺼내 버렸습니다**. 그래서 RET이 실행될 때 스택 맨 위에 있는 20을 복귀 주소로 착각하고 메모리 주소 20번지로 점프합니다. 그 주소는 프로그램 영역 밖이라 일반 보호 오류(general protection fault)가 납니다.

> 교훈: 프로시저 안에서 POP을 먼저 하면 복귀 주소를 날립니다.

---

### 17. 다음 코드 실행 시 EAX 값은?

```asm
 1: main PROC
 2:     mov eax,30
 3:     push eax
 4:     push 40
 5:     call Ex3Sub
 6:     INVOKE ExitProcess,0
 7: main ENDP
 8:
 9: Ex3Sub PROC
10:     pusha
11:     mov eax,80
12:     popa
13:     ret
14: Ex3Sub ENDP
```

**정답: 6번 줄에서 EAX = 30 입니다.**

10번 줄 `pusha`가 모든 레지스터를 저장하고, 12번 줄 `popa`가 원래 값으로 되돌립니다. 11번 줄에서 EAX를 80으로 바꿨지만 POPA가 **30으로 복원**합니다.

> 주의: 16비트 명령어인 PUSHA/POPA를 32비트 프로그램에서 쓰면 문제가 됩니다. 여기서는 개념 문제이므로 복원 동작에 초점을 둡니다.
> 또 하나, 스택에 넣은 30과 40은 **정리되지 않은 채** 남아 있습니다. 메모리 누수입니다.

---

### 18. 다음 코드 실행 시 어떤 일이 일어나는가?

```asm
 1: main PROC
 2:     mov eax,40
 3:     push offset Here
 4:     jmp Ex4Sub
 5: Here:
 6:     mov eax,30
 7:     INVOKE ExitProcess,0
 8: main ENDP
 9:
10: Ex4Sub PROC
11:     ret
12: Ex4Sub ENDP
```

**정답: 7번 줄에서 EAX = 30 입니다.**

이 코드는 CALL 없이 **CALL을 흉내 낸** 것입니다.

1. 3번 줄에서 `Here` 레이블의 주소를 직접 스택에 넣습니다. CALL이 복귀 주소를 넣는 것과 같은 효과입니다.
2. 4번 줄 JMP로 Ex4Sub으로 이동합니다.
3. 11번 줄 RET이 스택에서 `Here` 주소를 꺼내 EIP에 넣습니다.
4. 5번 줄 `Here:` 로 돌아와 6번 줄이 실행되어 EAX = 30 이 됩니다.

> CALL = PUSH(복귀주소) + JMP 라는 점을 보여 주는 문제입니다.

---

### 19. 다음 코드 실행 시 어떤 일이 일어나는가?

```asm
 1: main PROC
 2:     mov edx,0
 3:     mov eax,40
 4:     push eax
 5:     call Ex5Sub
 6:     INVOKE ExitProcess,0
 7: main ENDP
 8:
 9: Ex5Sub PROC
10:     pop eax
11:     pop edx
12:     push eax
13:     ret
14: Ex5Sub ENDP
```

**정답: 6번 줄에서 EDX = 40 입니다.**

스택을 따라가 봅니다.

| 단계 | 스택 (위 → 아래) | 레지스터 |
|---|---|---|
| `push eax` | 40 | EAX=40, EDX=0 |
| `call Ex5Sub` | 복귀주소, 40 | |
| 10번 `pop eax` | 40 | EAX = 복귀주소 |
| 11번 `pop edx` | (비어 있음) | **EDX = 40** |
| 12번 `push eax` | 복귀주소 | |
| 13번 `ret` | (비어 있음) | 정상 복귀 |

복귀 주소를 꺼냈다가 인자를 읽은 뒤 **다시 넣어** 정상적으로 돌아옵니다. 스택 인자에 접근하는 (권장되지는 않는) 기법입니다.

> 16번 문제와 비교해 보세요. 거기서는 복귀 주소를 복원하지 않아 오류가 났습니다.

---

### 20. 다음 코드 실행 후 배열에 들어가는 값은?

```asm
.data
array DWORD 4 DUP(0)
.code
main PROC
    mov eax,10
    mov esi,0
    call proc_1
    add esi,4
    add eax,10
    mov array[esi],eax
    INVOKE ExitProcess,0
main ENDP

proc_1 PROC
    call proc_2
    add esi,4
    add eax,10
    mov array[esi],eax
    ret
proc_1 ENDP

proc_2 PROC
    call proc_3
    add esi,4
    add eax,10
    mov array[esi],eax
    ret
proc_2 ENDP

proc_3 PROC
    mov array[esi],eax
    ret
proc_3 ENDP
```

**정답: array = [10, 20, 30, 40]**

호출이 가장 깊은 곳까지 내려갔다가 **되돌아 나오면서** 값을 씁니다.

| 순서 | 위치 | ESI | EAX | 동작 |
|---|---|---|---|---|
| 1 | main 시작 | 0 | 10 | 초기화 |
| 2 | proc_3 | 0 | 10 | `array[0] = 10` |
| 3 | proc_2 복귀 후 | 4 | 20 | `array[4] = 20` |
| 4 | proc_1 복귀 후 | 8 | 30 | `array[8] = 30` |
| 5 | main 복귀 후 | 12 | 40 | `array[12] = 40` |

**핵심**: main → proc_1 → proc_2 → proc_3 으로 내려가는 동안에는 아무것도 쓰지 않습니다. proc_3이 먼저 쓰고, 그 뒤 호출 스택을 거슬러 올라오며 차례로 씁니다.

배열 인덱스로 보면 `array[0]=10, array[1]=20, array[2]=30, array[3]=40` 입니다(더블워드 단위).

## 5.8.2 알고리즘 연습 (Algorithm Workbench)

### 1. PUSH와 POP만 써서 EAX와 EBX의 값을 교환하시오

```asm
push eax
push ebx
pop  eax            ; EAX ← 이전 EBX
pop  ebx            ; EBX ← 이전 EAX
```

**동작 확인** (EAX=1, EBX=2 로 가정)

| 단계 | 스택 (위 → 아래) | EAX | EBX |
|---|---|---|---|
| 시작 | — | 1 | 2 |
| `push eax` | 1 | 1 | 2 |
| `push ebx` | 2, 1 | 1 | 2 |
| `pop eax` | 1 | **2** | 2 |
| `pop ebx` | — | 2 | **1** |

> 핵심: 같은 순서로 PUSH 하고 **같은 순서로** POP 하면 교환됩니다. 역순으로 POP 하면 원래대로 복원됩니다.
> 64비트는 RAX, RBX로 바꾸면 됩니다.

---

### 2. 복귀 주소보다 3바이트 뒤로 돌아가게 만드는 명령어

RET 직전에 스택에 있는 복귀 주소에 3을 더합니다.

```asm
MySub PROC
    ; ... 작업 ...
    add DWORD PTR [esp],3       ; 스택 맨 위(복귀 주소)에 3을 더함
    ret
MySub ENDP
```

**원리**: RET은 `[esp]`의 값을 EIP에 넣습니다. 그 값을 미리 3 늘려 두면 호출한 쪽에서 3바이트 건너뛴 위치로 돌아갑니다.

> 실제로 이 기법은 CALL 바로 뒤에 데이터를 박아 둔 코드에서 그 데이터를 건너뛸 때 쓰입니다. 64비트는 `add QWORD PTR [rsp],3` 입니다.

---

### 3. 정수 더블워드 지역 변수 두 개를 위한 공간을 확보하고 1000h, 2000h를 대입하시오

```asm
MySub PROC
    push ebp                    ; 이전 프레임 포인터 저장
    mov  ebp,esp                ; 현재 프레임 기준점 설정
    sub  esp,8                  ; 지역 변수 2개(4바이트 × 2) 공간 확보

    mov  DWORD PTR [ebp-4],1000h    ; 첫 번째 지역 변수
    mov  DWORD PTR [ebp-8],2000h    ; 두 번째 지역 변수

    mov  esp,ebp                ; 지역 변수 공간 해제
    pop  ebp                    ; 프레임 포인터 복원
    ret
MySub ENDP
```

**핵심**
- 지역 변수는 **EBP보다 낮은 주소**에 잡힙니다(`[ebp-4]`, `[ebp-8]`).
- `sub esp,8` 로 공간을 확보하고, 끝에 `mov esp,ebp` 로 되돌립니다.
- 이 정리를 빼먹으면 RET이 엉뚱한 주소로 돌아갑니다.

> `enter 8,0` 과 `leave` 로 같은 일을 할 수 있습니다(8장 내용).

---

### 4. 인덱스 주소 지정으로 더블워드 배열의 원소를 바로 앞 위치로 복사하시오

```asm
.data
array DWORD 10,20,30,40,50

.code
    mov esi,TYPE array                  ; 두 번째 원소부터 시작 (인덱스 4)
    mov ecx,LENGTHOF array - 1          ; 이동 횟수 = 4
L1:
    mov eax,array[esi]                  ; 현재 원소를
    mov array[esi-4],eax                ; 바로 앞 자리에 복사
    add esi,TYPE array
    loop L1
    ; 결과: 20,30,40,50,50
```

**핵심**
- 첫 원소에는 앞자리가 없으므로 **두 번째부터** 시작합니다.
- 반드시 **앞에서 뒤로** 진행해야 합니다. 뒤에서부터 하면 아직 복사하지 않은 값을 덮어씁니다.
- 메모리끼리 직접 옮길 수 없어 EAX를 경유합니다.

### 5. 프로시저의 복귀 주소를 화면에 표시하시오 (복귀에 지장이 없어야 함)

```asm
ShowRetAddr PROC
    push eax                    ; 레지스터 보존

    mov eax,[esp+4]             ; 복귀 주소 읽기 (PUSH한 EAX 아래)
    call WriteHex               ; 16진수로 표시
    call Crlf

    pop  eax                    ; 복원
    ret
ShowRetAddr ENDP
```

**오프셋 계산이 핵심입니다.**

| 스택 위치 | 내용 |
|---|---|
| `[esp]` | 방금 PUSH한 EAX |
| `[esp+4]` | **복귀 주소** |

EAX를 하나 PUSH했으므로 복귀 주소는 4바이트 위에 있습니다. PUSH를 두 개 했다면 `[esp+8]` 이 됩니다.

**PUSH 없이 쓰는 방법**
```asm
ShowRetAddr PROC
    mov eax,[esp]               ; PUSH 전이므로 바로 맨 위가 복귀 주소
    call WriteHex
    ret
ShowRetAddr ENDP
```
단, 이 경우 EAX가 덮어써집니다.

**EBP를 쓰는 방법**
```asm
ShowRetAddr PROC
    push ebp
    mov  ebp,esp
    push eax

    mov  eax,[ebp+4]            ; 복귀 주소는 항상 [ebp+4]
    call WriteHex

    pop  eax
    pop  ebp
    ret
ShowRetAddr ENDP
```
> EBP를 기준점으로 잡으면 중간에 PUSH를 몇 번 하든 복귀 주소는 **항상 `[ebp+4]`** 입니다. 8장에서 배울 스택 프레임의 기본 원리입니다.

## 5.9 프로그래밍 과제 (Programming Exercises)

### 1. 텍스트 색상 바꾸기 ★

**문제**: 같은 문자열을 네 가지 색으로 표시하시오. SetTextColor를 루프에서 호출합니다.

```asm
INCLUDE Irvine32.inc

.data
msg BYTE "Assembly Language",0dh,0ah,0

.code
main PROC
    mov ecx,4                   ; 4번 반복
    mov ebx,1                   ; 시작 색상 (blue)

L1:
    push ecx                    ; 루프 카운터 보존!

    mov eax,ebx                 ; 전경색 지정
    call SetTextColor

    mov edx,OFFSET msg
    call WriteString

    inc ebx                     ; 다음 색
    pop ecx                     ; 카운터 복원
    loop L1

    mov eax,lightGray           ; 기본 색으로 되돌림
    call SetTextColor
    exit
main ENDP
END main
```

**핵심**
- **SetTextColor가 EAX를 쓰므로** 색상 값을 EAX에 넣어야 합니다.
- 라이브러리 프로시저가 ECX를 바꿀 수 있으니 **PUSH/POP으로 카운터를 보호**합니다.
- 배경색까지 지정하려면 `mov eax, yellow + (blue * 16)` 처럼 씁니다.

### 2. 연결된 배열 항목 따라가기 ★★

**문제**: 시작 인덱스, 문자 배열, 링크 배열이 주어졌을 때 링크를 따라가며 문자를 순서대로 모으시오.

예시 데이터
```
start = 1
chars: H A C E B D F G
links: 0 4 5 6 2 3 7 0
```
인덱스 1에서 시작해 `chars[1]='A'`, 다음은 `links[1]=4` → `chars[4]='B'` … 이런 식으로 따라갑니다.

```asm
INCLUDE Irvine32.inc

COUNT = 8

.data
chars  BYTE  'H','A','C','E','B','D','F','G'
links  DWORD 0,4,5,6,2,3,7,0        ; 더블워드 배열
output BYTE  COUNT DUP(0),0
start  DWORD 1

.code
main PROC
    mov esi,start               ; 현재 인덱스
    mov edi,0                   ; 출력 위치
    mov ecx,COUNT

L1:
    mov al,chars[esi]           ; 현재 인덱스의 문자
    mov output[edi],al          ; 출력 버퍼에 저장
    inc edi

    mov esi,links[esi*4]        ; 다음 인덱스 (더블워드라 ×4)
    loop L1

    mov edx,OFFSET output
    call WriteString
    call Crlf
    exit
main ENDP
END main
```

**핵심**
- `chars`는 BYTE 배열이라 `chars[esi]` 로 바로 접근합니다.
- `links`는 DWORD 배열이라 **`links[esi*4]`** 로 비례 계수를 씁니다. 여기서 실수하기 쉽습니다.
- 인덱스를 담는 ESI가 매 반복마다 링크 값으로 **갱신**됩니다.

### 3. 단순 덧셈 (1) ★

**문제**: 화면을 지우고 커서를 가운데 근처로 옮긴 뒤 정수 두 개를 입력받아 합을 표시하시오.

```asm
INCLUDE Irvine32.inc

.data
prompt1 BYTE "First integer:  ",0
prompt2 BYTE "Second integer: ",0
sumMsg  BYTE "The sum is: ",0

.code
main PROC
    call Clrscr

    mov dh,10                   ; 행 10
    mov dl,20                   ; 열 20
    call Gotoxy

    mov edx,OFFSET prompt1
    call WriteString
    call ReadInt                ; → EAX
    mov ebx,eax                 ; 첫 수 보관

    mov dh,11
    mov dl,20
    call Gotoxy
    mov edx,OFFSET prompt2
    call WriteString
    call ReadInt                ; → EAX

    add eax,ebx                 ; 합계

    mov dh,13
    mov dl,20
    call Gotoxy
    mov edx,OFFSET sumMsg
    call WriteString
    call WriteInt               ; EAX 표시
    call Crlf

    exit
main ENDP
END main
```

**핵심**
- `Gotoxy`는 **DH=행, DL=열** 입니다. 순서를 헷갈리기 쉽습니다.
- `ReadInt`는 결과를 EAX로 돌려주므로, 두 번째 입력 전에 **첫 값을 다른 레지스터로 옮겨야** 합니다.
- `WriteInt`는 부호 있는 정수, `WriteDec`는 부호 없는 정수를 표시합니다.

### 5. BetterRandomRange 프로시저 ★★

**문제**: M 이상 N−1 이하의 난수를 만드는 프로시저를 작성하시오. EBX에 하한 M, EAX에 상한 N을 받습니다.

```asm
INCLUDE Irvine32.inc

.data
lowerBound SDWORD -300
upperBound SDWORD 100

.code
main PROC
    call Randomize              ; 난수 생성기 초기화

    mov ecx,50                  ; 50번 테스트
L1:
    push ecx

    mov ebx,lowerBound
    mov eax,upperBound
    call BetterRandomRange      ; → EAX

    call WriteInt
    mov al,' '
    call WriteChar

    pop ecx
    loop L1

    call Crlf
    exit
main ENDP

;---------------------------------------------------
; BetterRandomRange
; M 이상 N-1 이하의 난수를 생성한다.
; Receives: EBX = 하한(M), EAX = 상한(N)
; Returns:  EAX = 난수
;---------------------------------------------------
BetterRandomRange PROC USES ebx
    sub eax,ebx                 ; 범위 폭 = N - M
    call RandomRange            ; 0 ~ (폭-1) 사이 난수
    add eax,ebx                 ; 하한만큼 이동
    ret
BetterRandomRange ENDP
END main
```

**원리**
1. 범위의 **폭**을 구합니다. N − M
2. `RandomRange`로 0 ~ 폭−1 의 난수를 얻습니다.
3. 하한 M을 더해 원하는 구간으로 옮깁니다.

예를 들어 M=−300, N=100 이면 폭은 400입니다. 0~399 난수에 −300을 더하면 −300~99 가 됩니다.

> `USES ebx`를 썼지만 반환값인 EAX는 넣지 않았습니다.

### 6. 무작위 문자열 ★★

**문제**: 길이 L의 대문자 무작위 문자열을 만드는 프로시저를 작성하시오. EAX에 길이, 포인터를 함께 받습니다.

```asm
INCLUDE Irvine32.inc

.data
buffer BYTE 21 DUP(0)           ; 최대 20자 + 널

.code
main PROC
    call Randomize

    mov ecx,20                  ; 20개 문자열 생성
L1:
    push ecx

    mov eax,10                  ; 길이 10
    mov edx,OFFSET buffer
    call RandomString

    mov edx,OFFSET buffer
    call WriteString
    call Crlf

    pop ecx
    loop L1

    exit
main ENDP

;---------------------------------------------------
; RandomString
; 무작위 대문자 문자열을 생성한다.
; Receives: EAX = 길이, EDX = 버퍼 주소
; Returns:  버퍼에 널 종료 문자열
;---------------------------------------------------
RandomString PROC USES eax ecx edx esi
    mov ecx,eax                 ; 길이를 카운터로
    mov esi,edx                 ; 버퍼 포인터

L1:
    push ecx                    ; 카운터 보존

    mov eax,26                  ; 알파벳 26자
    call RandomRange            ; 0 ~ 25
    add al,'A'                  ; ASCII 대문자로 변환
    mov [esi],al
    inc esi

    pop ecx
    loop L1

    mov BYTE PTR [esi],0        ; 널 종료자
    ret
RandomString ENDP
END main
```

**핵심**
- `RandomRange`가 0~25를 주면 **'A'(41h)를 더해** 대문자로 바꿉니다.
- `RandomRange`가 EAX를 쓰므로 루프 카운터는 **ECX에 두고 PUSH/POP으로 보호**합니다.
- 마지막에 **널 종료자**를 넣어야 WriteString이 제대로 동작합니다.

### 7. 무작위 화면 위치 ★

**문제**: 한 문자를 무작위 위치 100곳에 표시하되 100밀리초씩 지연하시오.

```asm
INCLUDE Irvine32.inc

.data
rows BYTE ?
cols BYTE ?

.code
main PROC
    call Randomize
    call Clrscr

    call GetMaxXY               ; AL = 행 수, DL = 열 수
    mov rows,al
    mov cols,dl

    mov ecx,100
L1:
    push ecx

    ; 무작위 행
    movzx eax,rows
    call RandomRange            ; 0 ~ rows-1
    mov dh,al

    ; 무작위 열
    push edx                    ; DH 보존
    movzx eax,cols
    call RandomRange            ; 0 ~ cols-1
    pop edx
    mov dl,al

    call Gotoxy

    mov al,'*'
    call WriteChar

    mov eax,100                 ; 100ms 지연
    call Delay

    pop ecx
    loop L1

    call Crlf
    exit
main ENDP
END main
```

**핵심**
- `GetMaxXY`로 실제 창 크기를 얻어야 범위를 벗어나지 않습니다.
- DH를 설정한 뒤 RandomRange를 다시 부르면 **EDX가 망가질 수 있으므로** PUSH/POP으로 보호합니다.
- `Delay`는 EAX에 밀리초를 받습니다.

### 8. 색상 행렬 ★★

**문제**: 전경색과 배경색의 모든 조합(16 × 16 = 256)으로 한 문자를 표시하시오.

```asm
INCLUDE Irvine32.inc

.data
ch BYTE 'X'

.code
main PROC
    call Clrscr

    mov ecx,16                  ; 배경색 16가지
    mov bh,0                    ; 배경색 번호

L1:
    push ecx
    mov ecx,16                  ; 전경색 16가지
    mov bl,0                    ; 전경색 번호

L2:
    ; 색상 = 전경색 + (배경색 × 16)
    movzx eax,bh
    shl eax,4                   ; 배경색을 상위 4비트로
    movzx edx,bl
    or  eax,edx                 ; 전경색 결합
    call SetTextColor

    mov al,ch
    call WriteChar

    inc bl                      ; 다음 전경색
    loop L2

    pop ecx
    call Crlf                   ; 줄바꿈
    inc bh                      ; 다음 배경색
    loop L1

    ; 기본 색 복원
    mov eax,lightGray
    call SetTextColor
    call Crlf
    exit
main ENDP
END main
```

**핵심**
- 색상 속성 바이트는 **상위 4비트가 배경, 하위 4비트가 전경**입니다.
- `shl eax,4` 는 16을 곱하는 것과 같습니다. `배경색 * 16 + 전경색` 으로 계산해도 됩니다.
- **중첩 루프**이므로 바깥 카운터를 PUSH/POP으로 보호합니다.

### 9. 재귀 프로시저 ★★★

**문제**: 자기 자신을 호출하는 프로시저를 만들고, 호출 횟수를 세는 카운터를 두시오. LOOP만 써서 정해진 횟수만큼 재귀하게 하시오.

```asm
INCLUDE Irvine32.inc

.data
counter DWORD 0
msg     BYTE "Recursion count: ",0

.code
main PROC
    mov ecx,5                   ; 재귀 횟수
    call RecursiveProc

    mov edx,OFFSET msg
    call WriteString
    mov eax,counter
    call WriteDec
    call Crlf

    exit
main ENDP

;---------------------------------------------------
; RecursiveProc
; ECX 값만큼 자기 자신을 재귀 호출한다.
; Receives: ECX = 재귀 횟수
; Returns:  counter에 호출 횟수 누적
;---------------------------------------------------
RecursiveProc PROC
    inc counter                 ; 호출 횟수 증가
    call RecursiveProc_Helper   ; (LOOP가 재귀를 일으키도록)
    ret
RecursiveProc ENDP
```

LOOP만 써서 재귀를 제어하는 방식은 이렇습니다.

```asm
RecursiveProc PROC
    inc counter                 ; 1. 호출 기록
    loop RecursiveProc          ; 2. ECX를 줄이고 0이 아니면 다시 진입
    ret                         ; 3. ECX = 0이면 복귀
RecursiveProc ENDP
```

**동작 설명**
- `loop RecursiveProc` 가 프로시저의 **맨 앞으로 점프**합니다. CALL이 아니라 JMP이므로 스택에 복귀 주소가 쌓이지는 않지만, 논리적으로는 자기 자신을 반복 실행하는 셈입니다.
- ECX가 0이 되면 LOOP가 더 이상 점프하지 않고 RET으로 진행합니다.
- 실행 후 `counter = 5` 입니다.

**진짜 재귀(CALL 사용) 버전**
```asm
RecursiveProc PROC
    inc counter
    dec ecx
    cmp ecx,0
    je  L1                      ; 종료 조건
    call RecursiveProc          ; 재귀 호출
L1: ret
RecursiveProc ENDP
```
> 이쪽은 호출마다 **복귀 주소 4바이트가 스택에 쌓입니다**. 종료 조건이 없으면 스택 오버플로가 납니다.

### 10. 피보나치 생성기 ★★★

**문제**: N개의 피보나치 수를 만들어 더블워드 배열에 저장하는 프로시저를 작성하시오. 배열 포인터와 개수를 받습니다. N = 47로 테스트합니다.

```asm
INCLUDE Irvine32.inc

COUNT = 47

.data
fibArray DWORD COUNT DUP(?)

.code
main PROC
    mov esi,OFFSET fibArray
    mov ecx,COUNT
    call Fibonacci

    ; 확인용 출력 (처음 10개)
    mov esi,OFFSET fibArray
    mov ecx,10
L1:
    mov eax,[esi]
    call WriteDec
    mov al,' '
    call WriteChar
    add esi,4
    loop L1
    call Crlf

    exit
main ENDP

;---------------------------------------------------
; Fibonacci
; 피보나치 수열을 배열에 생성한다.
; Receives: ESI = 배열 주소, ECX = 생성할 개수
; Returns:  배열에 수열 저장
;---------------------------------------------------
Fibonacci PROC USES eax ebx ecx esi
    cmp ecx,0
    je  done                    ; 개수가 0이면 종료

    mov DWORD PTR [esi],1       ; 첫 항 = 1
    dec ecx
    jz  done                    ; 1개만 요청했으면 끝

    add esi,4
    mov DWORD PTR [esi],1       ; 둘째 항 = 1
    dec ecx
    jz  done                    ; 2개만 요청했으면 끝

    mov eax,1                   ; 이전 항
    mov ebx,1                   ; 현재 항

L1:
    add esi,4
    mov edx,eax                 ; 임시 보관
    add edx,ebx                 ; 새 항 = 이전 + 현재
    mov [esi],edx               ; 저장

    mov eax,ebx                 ; 이전 ← 현재
    mov ebx,edx                 ; 현재 ← 새 항
    loop L1

done:
    ret
Fibonacci ENDP
END main
```

**핵심**
- 첫 두 항은 **루프 밖에서** 직접 넣습니다. 이전 항이 없기 때문입니다.
- 개수가 1이나 2일 때를 **따로 처리**해야 합니다. 안 그러면 배열 밖을 씁니다.
- 세 변수(이전, 현재, 새 항)를 순환시키는 것이 핵심입니다.
- 47번째 항은 **2,971,215,073** 으로 32비트 부호 없는 범위(약 42억) 안에 겨우 들어갑니다. 48번째는 넘칩니다.

### 11. K의 배수 찾기 ★★★

**문제**: 크기 N의 바이트 배열에서 N 미만인 K의 배수 위치에 1을 표시하시오. K=2와 K=3으로 두 번 호출합니다.

```asm
INCLUDE Irvine32.inc

ARRAY_SIZE = 50

.data
sieve BYTE ARRAY_SIZE DUP(0)

.code
main PROC
    ; 2의 배수 표시
    mov esi,OFFSET sieve
    mov ecx,ARRAY_SIZE
    mov ebx,2
    call MarkMultiples

    ; 3의 배수 표시
    mov esi,OFFSET sieve
    mov ecx,ARRAY_SIZE
    mov ebx,3
    call MarkMultiples

    ; 확인용 출력
    mov esi,OFFSET sieve
    mov ecx,ARRAY_SIZE
    mov edi,0
L1:
    movzx eax,BYTE PTR [esi]
    call WriteDec
    mov al,' '
    call WriteChar
    inc esi
    loop L1
    call Crlf

    exit
main ENDP

;---------------------------------------------------
; MarkMultiples
; 배열에서 K의 배수 위치를 1로 표시한다.
; Receives: ESI = 배열 주소, ECX = 배열 크기, EBX = K
; Returns:  nothing
;---------------------------------------------------
MarkMultiples PROC USES eax ebx ecx esi
    cmp ebx,2
    jb  done                    ; K < 2면 무의미

    mov eax,ebx                 ; 첫 배수 = K

L1:
    cmp eax,ecx                 ; 배열 크기를 넘었나?
    jae done                    ; 그러면 종료

    mov BYTE PTR [esi+eax],1    ; 해당 위치 표시
    add eax,ebx                 ; 다음 배수
    jmp L1

done:
    ret
MarkMultiples ENDP
END main
```

**핵심**
- 인덱스를 EAX에 두고 **K씩 더하며** 진행합니다. 나눗셈이 필요 없습니다.
- 종료 조건은 **LOOP가 아니라 `cmp eax,ecx`** 입니다. 반복 횟수가 N이 아니라 N/K 이기 때문입니다.
- `[esi+eax]` 처럼 기준 주소와 인덱스를 더해 접근합니다.
- 이 알고리즘이 **에라토스테네스의 체**의 기본 뼈대입니다. 6장에서 배울 조건문을 쓰면 소수를 걸러낼 수 있습니다.

| 명령어 | 동작 순서 |
|---|---|
| **PUSH** | ESP를 4 **감소** → 그 자리에 저장 |
| **POP** | 값을 읽음 → ESP를 4 **증가** |
| **CALL** | 복귀 주소를 **PUSH** → 프로시저로 점프 |
| **RET** | 복귀 주소를 **POP** 해서 EIP에 |

> `CALL` = `PUSH(복귀주소)` + `JMP`

## 스택 추적 문제 푸는 법

1. 표를 그려 스택의 위에서 아래 순서로 적습니다
2. CALL이 나오면 **복귀 주소도 빠뜨리지 말고** 적습니다
3. POP 할 때마다 무엇이 나오는지 확인합니다
4. RET 시점에 맨 위가 복귀 주소인지 **반드시 점검**합니다

## 레지스터 보존 규칙

- 프로시저가 바꾸는 레지스터는 PUSH/POP 또는 USES로 보존합니다
- **POP은 PUSH의 역순**입니다
- **반환값 레지스터(보통 EAX)는 보존하지 않습니다**
- USES의 레지스터 목록은 **공백**으로 구분합니다

## 라이브러리 호출 시 주의

| 프로시저 | 입력 | 출력 |
|---|---|---|
| Gotoxy | **DH=행, DL=열** | — |
| ReadInt / ReadDec | — | EAX |
| WriteInt / WriteDec | EAX | — |
| WriteString | EDX = 문자열 주소 | — |
| ReadString | EDX=버퍼, ECX=최대길이 | EAX=실제길이 |
| SetTextColor | EAX = 색상 | — |
| RandomRange | EAX = n | EAX = 0~n−1 |
| Delay | EAX = 밀리초 | — |
| GetMaxXY | — | AL=행 수, DL=열 수 |

⭐ 라이브러리 프로시저는 레지스터를 바꾸므로 **루프 카운터 ECX를 PUSH/POP으로 보호**하는 습관을 들이세요.

## 자주 나오는 함정

- 프로시저 안에서 POP을 먼저 하면 **복귀 주소를 잃습니다**
- PUSHAD/POPAD는 **EAX까지 복원**하므로 반환값이 있으면 쓰면 안 됩니다
- 스택에 PUSH한 인자는 **누군가 정리해야** 합니다
- 중첩 루프에서 바깥 ECX를 보호하지 않으면 무한 루프가 됩니다
