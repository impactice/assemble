> 문제는 한국어로 요약했습니다. 원문은 교재 134~138쪽을 함께 보세요.

## 4.9.1 단답형 (Short Answer)

### 1. 다음 코드에서 (a), (b) 실행 후 EDX 값은?

```asm
.data
one WORD 8002h
two WORD 4321h
.code
mov edx,21348041h
movsx edx,one        ; (a)
movsx edx,two        ; (b)
```

**(a) EDX = FFFF8002h**
`one`은 8002h이고 MSB가 1(8 ≥ 8)이라 음수입니다. MOVSX는 부호 확장이므로 상위 16비트를 모두 1로 채웁니다.

**(b) EDX = 00004321h**
`two`는 4321h이고 MSB가 0(4 ≤ 7)이라 양수입니다. 상위 16비트를 0으로 채웁니다.

> 핵심: MOVSX는 **원본의 최상위 비트를 복제**해 채웁니다. 16진수 첫 자리가 8~F면 1로, 0~7이면 0으로 채워집니다.

---

### 2. 실행 후 EAX 값은?

```asm
mov eax,1002FFFFh
inc ax
```

**EAX = 10020000h**

`inc ax`는 **하위 16비트만** 1 증가시킵니다. FFFFh + 1 = 10000h인데 16비트에 담기지 않아 0000h만 남습니다. 자리올림이 상위 16비트(1002h)로 넘어가지 **않습니다**.

> 핵심: 부분 레지스터 연산은 나머지 비트를 건드리지 않습니다.

---

### 3. 실행 후 EAX 값은?

```asm
mov eax,30020000h
dec ax
```

**EAX = 3002FFFFh**

AX = 0000h에서 1을 빼면 FFFFh가 됩니다. 빌림이 상위 16비트로 전파되지 않으므로 3002h는 그대로입니다.

---

### 4. 실행 후 EAX 값은?

```asm
mov eax,1002FFFFh
neg ax
```

**EAX = 10020001h**

AX = FFFFh의 2의 보수를 구합니다. 비트 반전하면 0000h, 1을 더하면 0001h입니다. (FFFFh는 −1이고, −(−1) = +1입니다.)

---

### 5. 실행 후 Parity 플래그 값은?

```asm
mov al,1
add al,3
```

**PF = 1 (짝수 패리티)**

AL = 4 = `00000100b` 입니다. 1인 비트가 **1개**로 홀수입니다.

> 주의: x86의 Parity 플래그는 1 비트 개수가 **짝수일 때 세트**됩니다. 여기서는 1개(홀수)이므로 **PF = 0** 이 맞습니다.
>
> 정답은 **PF = 0** 입니다.

---

### 6. 실행 후 EAX와 Sign 플래그 값은?

```asm
mov eax,5
sub eax,6
```

**EAX = FFFFFFFFh (−1), SF = 1**

5 − 6 = −1 입니다. 결과의 MSB가 1이므로 Sign 플래그가 세트됩니다.

---

### 7. AL을 부호 있는 바이트로 볼 때, Overflow 플래그는 결과가 유효 범위 안에 있는지 판단하는 데 도움이 되는가?

```asm
mov al,-1
add al,130
```

**도움이 됩니다. OF = 0 이므로 부호 있는 결과는 유효합니다.**

단계별로 보면 이렇습니다.
- `-1` = FFh, `130` = 82h
- FFh + 82h = 181h → AL = 81h (상위 자리올림 버림, CF = 1)
- 81h를 부호 있는 값으로 읽으면 **−127**

부호 있는 관점에서 130은 8비트 범위(−128~+127)를 넘으므로 실제로는 −126으로 해석됩니다. 즉 (−1) + (−126) = −127 이고, 이는 범위 안이라 **OF = 0** 입니다.

> 핵심: 부호가 다른 두 수를 더하면(또는 부호 있는 관점에서 같은 부호라도 범위 안이면) 오버플로가 나지 않습니다. CF = 1 이지만 부호 있는 연산에서는 의미가 없습니다.

---

### 8. 실행 후 RAX 값은?

```asm
mov rax,44445555h
```

**RAX = 0000000044445555h**

64비트 레지스터에 32비트 상수를 넣으면 **상위 32비트가 0으로 지워집니다**.

---

### 9. 실행 후 RAX 값은?

```asm
.data
dwordVal DWORD 84326732h
.code
mov rax,0FFFFFFFF00000000h
mov rax,dwordVal
```

**RAX = 0000000084326732h**

32비트 **메모리 피연산자**를 EAX(= RAX의 하위 32비트)에 옮기면 상위 32비트가 0으로 지워집니다. 앞서 넣은 FFFFFFFFh는 사라집니다.

> 주의: 8비트·16비트 메모리를 옮길 때는 상위 비트가 **그대로 남습니다**. 32비트만 예외입니다.

---

### 10. 실행 후 EAX 값은?

```asm
.data
dVal DWORD 12345678h
.code
mov ax,3
mov WORD PTR dVal+2,ax
mov eax,dVal
```

**EAX = 00035678h**

리틀엔디언으로 `dVal`은 메모리에 `78 56 34 12` 로 들어 있습니다.

| 오프셋 | 초기값 | 변경 후 |
|---|---|---|
| dVal+0 | 78 | 78 |
| dVal+1 | 56 | 56 |
| dVal+2 | 34 | **03** |
| dVal+3 | 12 | **00** |

`dVal+2`에 워드 0003h를 쓰면 상위 워드가 0003h가 됩니다. 전체를 다시 읽으면 00035678h 입니다.

---

### 11. 실행 후 EAX 값은?

```asm
.data
dVal DWORD ?
.code
mov dVal,12345678h
mov ax,WORD PTR dVal+2
add ax,3
mov WORD PTR dVal,ax
mov eax,dVal
```

**EAX = 12341237h**

1. `dVal` = 12345678h → 메모리 `78 56 34 12`
2. `dVal+2`의 워드는 **1234h** → AX = 1234h
3. AX + 3 = **1237h**
4. `dVal`의 **하위** 워드에 1237h를 씀 → 메모리 `37 12 34 12`
5. 전체를 읽으면 **12341237h**

---

### 12. (예/아니오) 양수에 음수를 더해 Overflow 플래그가 세트될 수 있는가?

**아니오.**

부호가 서로 다른 두 수를 더하면 결과의 절대값이 둘 중 큰 쪽을 넘지 않습니다. 따라서 범위를 벗어날 수 없습니다.

---

### 13. (예/아니오) 음수에 음수를 더해 양수가 나오면 Overflow 플래그가 세트되는가?

**예.**

음수 + 음수 = 양수는 전형적인 부호 있는 오버플로입니다.

> 외울 것: **같은 부호끼리 더했는데 부호가 바뀌면 OF = 1**

---

### 14. (예/아니오) NEG 명령어가 Overflow 플래그를 세트할 수 있는가?

**예.**

```asm
mov al,-128         ; 10000000b
neg al              ; 결과가 +128인데 8비트 범위 초과 → OF = 1
```

부호 있는 8비트의 최솟값 −128은 양수 쪽에 대응하는 값(+128)이 없어 오버플로가 납니다.

---

### 15. (예/아니오) Sign 플래그와 Zero 플래그가 동시에 세트될 수 있는가?

**아니오.**

Zero 플래그는 결과가 0일 때 세트되는데, 0은 MSB가 0이라 Sign 플래그가 동시에 세트될 수 없습니다.

---

### 16. 다음 선언을 바탕으로 각 문장의 유효성을 판단하시오

```asm
.data
var1 SBYTE -4,-2,3,1
var2 WORD  1000h,2000h,3000h,4000h
var3 SWORD -16,-42
var4 DWORD 1,2,3,4,5
```

| 문장 | 유효성 | 이유 |
|---|---|---|
| (a) `mov ax,var1` | **무효** | AX는 16비트, var1은 8비트. 크기 불일치 |
| (b) `mov ax,var2` | **유효** | 둘 다 16비트 |
| (c) `mov eax,var3` | **무효** | EAX는 32비트, var3은 16비트 |
| (d) `mov var2,var3` | **무효** | 메모리 → 메모리 불가 |
| (e) `movzx ax,var2` | **무효** | MOVZX는 원본이 대상보다 **작아야** 함. 둘 다 16비트 |
| (f) `movzx var2,al` | **무효** | MOVZX의 대상은 **레지스터**여야 함 |
| (g) `mov ds,ax` | **유효** | 세그먼트 레지스터에 16비트 레지스터 대입은 가능 |
| (h) `mov ds,1000h` | **무효** | 세그먼트 레지스터에 **즉시값** 직접 대입 불가 |

---

### 17. 순서대로 실행했을 때 대상 피연산자의 16진 값은?

```asm
mov al,var1          ; (a)
mov ah,[var1+3]      ; (b)
```

**(a) AL = FCh**
`var1`의 첫 값은 −4 입니다. 8비트 2의 보수로 −4 = FCh 입니다.
(검산: 4 = 00000100b → 반전 11111011b → +1 → 11111100b = FCh)

**(b) AH = 01h**
`var1+3`은 네 번째 바이트인 1 입니다. SBYTE 배열이므로 1바이트씩 이동합니다.

---

### 18. 순서대로 실행했을 때 대상 피연산자의 값은?

```asm
mov ax,var2          ; (a)
mov ax,[var2+4]      ; (b)
mov ax,var3          ; (c)
mov ax,[var3-2]      ; (d)
```

**(a) AX = 1000h** — var2의 첫 워드

**(b) AX = 3000h** — 워드는 2바이트이므로 +4는 세 번째 원소

**(c) AX = FFF0h** — var3의 첫 값은 −16. 16비트 2의 보수로 FFF0h
(검산: 16 = 0010h → 반전 FFEFh → +1 → FFF0h)

**(d) AX = 4000h** — `var3-2`는 var3 바로 앞, 즉 var2의 마지막 원소 4000h

> 핵심: 변수들은 선언 순서대로 메모리에 연속 배치됩니다. 음수 변위로 앞 변수에 접근할 수 있습니다.

---

### 19. 순서대로 실행했을 때 EDX 값은?

```asm
mov edx,var4         ; (a)
movzx edx,var2       ; (b)
mov edx,[var4+4]     ; (c)
movsx edx,var1       ; (d)
```

**(a) EDX = 00000001h** — var4의 첫 더블워드

**(b) EDX = 00001000h** — var2의 첫 워드 1000h를 영 확장

**(c) EDX = 00000002h** — 더블워드는 4바이트이므로 +4는 두 번째 원소

**(d) EDX = FFFFFFFCh** — var1의 첫 값 −4(FCh)를 부호 확장. MSB가 1이므로 상위를 F로 채움

## 4.9.2 알고리즘 연습 (Algorithm Workbench)

### 1. doubleword 변수 three의 상위 워드와 하위 워드를 교환하는 MOV 명령어 나열

```asm
.data
three DWORD 12345678h
.code
mov ax,WORD PTR three           ; AX = 5678h (하위)
mov bx,WORD PTR [three+2]       ; BX = 1234h (상위)
mov WORD PTR three,bx           ; 하위에 1234h
mov WORD PTR [three+2],ax       ; 상위에 5678h
; 결과: three = 56781234h
```

> `ror three,16` 한 줄로도 됩니다(7장 내용).

---

### 2. XCHG를 **세 번 이하** 써서 8비트 레지스터 네 개를 A,B,C,D → B,C,D,A 로 바꾸기

A=AL, B=BL, C=CL, D=DL 이라 하고, 각 레지스터의 **값**을 왼쪽으로 한 칸씩 회전시킵니다.

```asm
xchg al,bl          ; AL=B, BL=A
xchg bl,cl          ; BL=C, CL=A
xchg cl,dl          ; CL=D, DL=A
; 결과: AL=B, BL=C, CL=D, DL=A
```

> 원리: A를 계속 뒤로 밀어내면서 나머지를 한 칸씩 당깁니다. n개를 회전시키려면 교환이 n−1번 필요합니다.

---

### 3. AL에 01110101이 있을 때, Parity 플래그로 짝수/홀수 패리티 판별

```asm
mov al,01110101b
or  al,0            ; 값은 그대로, 플래그만 갱신
jp  EvenParity      ; PF=1이면 짝수 패리티
jnp OddParity       ; PF=0이면 홀수 패리티
```

**판정**: `01110101b`의 1 비트는 0,2,4,5,6 번 자리로 **5개(홀수)** 입니다. 따라서 **PF = 0, 홀수 패리티** 입니다.

> `or al,0`, `and al,0FFh`, `test al,al`, `xor al,0` 모두 값을 유지하면서 플래그만 바꿉니다.

### 8. 비례 계수와 인덱스 주소 지정으로 doubleword 배열의 합 구하기

```asm
.code
```

### 10. Carry와 Overflow를 동시에 세트하는 두 명령어

```asm
mov al,-128         ; 80h
sub al,1            ; 80h - 01h = 7Fh
; 부호 있는 관점: -128 - 1 = -129 → 범위 초과 → OF = 1
```

덧셈으로 하려면 이렇습니다.
```asm
mov al,80h          ; -128 (부호 있는) / 128 (부호 없는)
add al,80h          ; 결과 00h
; 부호 없는: 256 → 8비트 초과 → CF = 1
; 부호 있는: (-128) + (-128) = -256 → 범위 초과 → OF = 1
```

### 11. INC와 DEC 실행 후 Zero 플래그로 부호 없는 오버플로를 알아내는 코드

INC와 DEC는 **Carry 플래그를 바꾸지 않으므로** Zero 플래그로 판단해야 합니다.

```asm
; INC: 최댓값에서 1 증가 → 0으로 되돌아감
mov al,0FFh
inc al              ; AL = 00h → ZF = 1 (랩어라운드 발생)
jz  overflow_up

; DEC: 1에서 1 감소 → 0
mov al,1
dec al              ; AL = 00h → ZF = 1
; 0에서 한 번 더 감소하면 FFh (언더플로), 이때 ZF = 0
```

> 핵심: **INC/DEC는 CF를 수정하지 않는다**는 점이 이 문제의 출제 의도입니다.

### 13. 각 명령어 실행 후 EAX 값은?

| 문제 | 명령어 | EAX | 설명 |
|---|---|---|---|
| (a) | `mov eax,TYPE myBytes` | **1** | BYTE는 1바이트 |
| (b) | `mov eax,LENGTHOF myBytes` | **4** | 원소 4개 |
| (c) | `mov eax,SIZEOF myBytes` | **4** | 4 × 1 |
| (d) | `mov eax,TYPE myWords` | **2** | WORD는 2바이트 |
| (e) | `mov eax,LENGTHOF myWords` | **4** | `3 DUP(?)` 3개 + 2000h 1개 |
| (f) | `mov eax,SIZEOF myWords` | **8** | 4 × 2 |
| (g) | `mov eax,SIZEOF myString` | **5** | 문자 5개 × 1바이트 |

> 공식: **SIZEOF = LENGTHOF × TYPE**
> 주의: myString에는 널 종료자(`,0`)가 없으므로 5입니다. 있었다면 6이 됩니다.

### 15. myWords의 두 번째 바이트를 AL로 옮기는 명령어

```asm
mov al,BYTE PTR [myWords+1]
```

> myWords의 **두 번째 워드**가 아니라 **두 번째 바이트**입니다. 오프셋 1입니다.

## 4.10 프로그래밍 과제 (Programming Exercises)

### 1. 빅엔디언 → 리틀엔디언 변환 ★

**문제**: 주어진 변수를 MOV 명령어만 써서 바이트 순서를 뒤집어 복사하시오.

```asm
.data
bigEndian    BYTE 12h,34h,56h,78h
littleEndian DWORD ?
```

**풀이**: 바이트를 역순으로 하나씩 옮깁니다.

```asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
bigEndian    BYTE 12h,34h,56h,78h
littleEndian DWORD ?

.code
main PROC
    mov al,bigEndian            ; 12h
    mov BYTE PTR [littleEndian+3],al

    mov al,[bigEndian+1]        ; 34h
    mov BYTE PTR [littleEndian+2],al

    mov al,[bigEndian+2]        ; 56h
    mov BYTE PTR [littleEndian+1],al

    mov al,[bigEndian+3]        ; 78h
    mov BYTE PTR littleEndian,al

    ; littleEndian = 12345678h
    INVOKE ExitProcess,0
main ENDP
END main
```

> 확인: 메모리에는 `78 56 34 12` 로 저장되고, DWORD로 읽으면 12345678h 입니다.

### 2. 배열의 인접한 원소 쌍 교환 ★★

**문제**: 원소 개수가 짝수인 배열에서 i와 i+1, i+2와 i+3 … 을 서로 바꾸시오.

```asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
array DWORD 10,20,30,40,50,60

.code
main PROC
    mov esi,0
    mov ecx,LENGTHOF array / 2      ; 쌍의 개수 = 3

L1:
    mov eax,array[esi]              ; 첫 번째
    xchg eax,array[esi+4]           ; 두 번째와 교환
    mov array[esi],eax              ; 되돌려 저장
    add esi,8                       ; 다음 쌍으로 (4바이트 × 2)
    loop L1

    ; 결과: 20,10,40,30,60,50
    INVOKE ExitProcess,0
main ENDP
END main
```

**핵심**
- 반복 횟수는 원소 개수의 **절반**입니다.
- 인덱스는 한 번에 **8씩**(더블워드 2개) 증가합니다.
- 메모리끼리 직접 교환할 수 없어 레지스터를 거칩니다.

### 3. 배열 원소 간 차이의 합 ★★

**문제**: 비내림차순으로 정렬된 배열에서 인접 원소 간 간격의 합을 구하시오.
예: {0, 2, 5, 9, 10} → 간격 2, 3, 4, 1 → 합 10

```asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
array DWORD 0,2,5,9,10
sum   DWORD ?

.code
main PROC
    mov esi,0
    mov eax,0                       ; 합계
    mov ecx,LENGTHOF array - 1      ; 간격 개수 = 원소 수 - 1

L1:
    mov ebx,array[esi+4]            ; 다음 원소
    sub ebx,array[esi]              ; 간격 = 다음 - 현재
    add eax,ebx                     ; 누적
    add esi,4
    loop L1

    mov sum,eax                     ; sum = 10
    INVOKE ExitProcess,0
main ENDP
END main
```

> 참고: 정렬된 배열이라면 **마지막 원소 − 첫 원소** 가 바로 답입니다(10 − 0 = 10). 하지만 문제 의도대로 루프로 구현했습니다.

### 4. Word 배열을 Doubleword 배열로 복사 ★★

**문제**: 부호 없는 16비트 배열의 값을 32비트 배열로 복사하시오.

```asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
wordArray  WORD  1234h,5678h,9ABCh,0DEF0h
dwordArray DWORD LENGTHOF wordArray DUP(?)

.code
main PROC
    mov esi,0                       ; word 배열 인덱스
    mov edi,0                       ; dword 배열 인덱스
    mov ecx,LENGTHOF wordArray

L1:
    movzx eax,wordArray[esi]        ; 영 확장 (부호 없음!)
    mov dwordArray[edi],eax
    add esi,TYPE wordArray          ; +2
    add edi,TYPE dwordArray         ; +4
    loop L1

    INVOKE ExitProcess,0
main ENDP
END main
```

**핵심**
- 부호 **없는** 값이므로 **MOVZX**를 씁니다. 부호 있는 값이면 MOVSX입니다.
- 두 배열의 원소 크기가 달라 **인덱스를 따로** 관리합니다.

### 5. 피보나치 수열 ★★

**문제**: Fib(1)=1, Fib(2)=1, Fib(n)=Fib(n−1)+Fib(n−2) 로 앞 일곱 항을 계산하시오.

```asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
fib DWORD 7 DUP(?)

.code
main PROC
    mov fib,1                       ; Fib(1) = 1
    mov [fib+4],1                   ; Fib(2) = 1

    mov esi,8                       ; 세 번째 원소부터
    mov ecx,5                       ; 나머지 5개

L1:
    mov eax,[fib+esi-4]             ; 바로 앞 항
    add eax,[fib+esi-8]             ; 그 앞 항
    mov [fib+esi],eax               ; 저장
    add esi,4
    loop L1

    ; 결과: 1,1,2,3,5,8,13
    INVOKE ExitProcess,0
main ENDP
END main
```

**레지스터만 쓰는 더 간단한 방법**
```asm
    mov eax,1                       ; 현재 항
    mov ebx,1                       ; 이전 항
    mov ecx,5

L1: add eax,ebx                     ; 새 항 = 현재 + 이전
    sub eax,ebx                     ; 교환을 위한 처리
    xchg eax,ebx
    add eax,ebx
    loop L1
```
실제로는 다음이 더 명확합니다.
```asm
    mov eax,1
    mov ebx,1
    mov ecx,5
L1: mov edx,eax                     ; 현재 항 보관
    add eax,ebx                     ; 새 항
    mov ebx,edx                     ; 이전 항 갱신
    loop L1
```

### 6. 배열 뒤집기 ★★★

**문제**: 추가 배열 없이 제자리에서 정수 배열의 순서를 뒤집으시오. SIZEOF, TYPE, LENGTHOF를 써서 유연하게 작성하시오.

```asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
array DWORD 10,20,30,40,50,60

.code
main PROC
    mov esi,OFFSET array                        ; 앞쪽 포인터
    mov edi,OFFSET array + SIZEOF array - TYPE array  ; 뒤쪽 포인터
    mov ecx,LENGTHOF array / 2                  ; 교환 횟수

L1:
    mov eax,[esi]                               ; 앞 값
    mov ebx,[edi]                               ; 뒤 값
    mov [esi],ebx                               ; 교환
    mov [edi],eax
    add esi,TYPE array                          ; 앞은 전진
    sub edi,TYPE array                          ; 뒤는 후진
    loop L1

    ; 결과: 60,50,40,30,20,10
    INVOKE ExitProcess,0
main ENDP
END main
```

**핵심**
- 마지막 원소의 주소는 `OFFSET array + SIZEOF array − TYPE array` 입니다. SIZEOF만 더하면 배열 **바로 뒤**를 가리키므로 한 원소만큼 빼야 합니다.
- 교환 횟수는 원소 수의 **절반**입니다. 홀수 개면 가운데는 그대로 두면 되므로 정수 나눗셈으로 충분합니다.
- 두 포인터가 **서로 마주 보며** 이동합니다.

### 7. 문자열 역순 복사 ★★★

**문제**: source의 문자를 역순으로 target에 복사하시오.

```asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
source BYTE "This is the source string",0
target BYTE SIZEOF source DUP('#')

.code
main PROC
    mov esi,OFFSET source + SIZEOF source - 2   ; 마지막 문자 (널 제외)
    mov edi,OFFSET target                       ; 대상 처음
    mov ecx,SIZEOF source - 1                   ; 널을 뺀 문자 수

L1:
    mov al,[esi]                                ; 뒤에서부터 읽고
    mov [edi],al                                ; 앞에서부터 쓰기
    dec esi
    inc edi
    loop L1

    mov BYTE PTR [edi],0                        ; 널 종료자 추가
    INVOKE ExitProcess,0
main ENDP
END main
```

**핵심**
- `SIZEOF source`에는 널 종료자가 **포함**되므로, 마지막 문자를 가리키려면 **2를 빼야** 합니다.
- 반복 횟수는 `SIZEOF source − 1` (널 제외)입니다.
- ESI는 감소, EDI는 증가합니다.

### 8. 배열 원소 회전 ★★★

**문제**: 배열 원소를 앞으로 한 칸씩 밀고, 마지막 값을 첫 자리로 보내시오.
예: [10,20,30,40] → [40,10,20,30]

```asm
.386
.model flat,stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
array DWORD 10,20,30,40

.code
main PROC
    ; 1단계: 마지막 값을 임시 보관
    mov esi,SIZEOF array - TYPE array       ; 마지막 원소 오프셋
    mov eax,array[esi]                      ; EAX = 40

    ; 2단계: 뒤에서부터 앞 값을 한 칸씩 뒤로 복사
    mov ecx,LENGTHOF array - 1              ; 3번 이동
L1:
    mov ebx,array[esi-4]                    ; 앞 원소를
    mov array[esi],ebx                      ; 현재 자리에
    sub esi,TYPE array
    loop L1

    ; 3단계: 보관해 둔 값을 첫 자리에
    mov array,eax

    ; 결과: 40,10,20,30
    INVOKE ExitProcess,0
main ENDP
END main
```

**핵심**
- 반드시 **뒤에서 앞으로** 진행해야 합니다. 앞에서부터 하면 값을 덮어써서 잃어버립니다.
- 마지막 값은 루프 **전에** 따로 보관합니다.
- 이동 횟수는 원소 수 − 1 입니다.

# 4장 시험 대비 요점

## 계산 문제 체크리스트

**부분 레지스터**
- `inc ax`는 상위 16비트를 건드리지 않습니다
- AX = FFFFh 에서 inc → 0000h (자리올림 전파 없음)

**MOVZX / MOVSX**
- MOVZX: 상위를 0으로 (부호 없는 값)
- MOVSX: 상위를 **원본 MSB로** (부호 있는 값)
- 16진수 첫 자리 8~F → 음수 → F로 채움

**리틀엔디언**
- 12345678h → 메모리 `78 56 34 12`
- `WORD PTR var` = 하위 워드(5678h)
- `WORD PTR [var+2]` = 상위 워드(1234h)

**연산자**
- TYPE = 원소 1개의 바이트 수
- LENGTHOF = 원소 개수
- SIZEOF = LENGTHOF × TYPE
- `3 DUP(?)` 는 원소 **3개**로 셉니다

**플래그**
- CF: 부호 없는 범위 초과
- OF: 부호 있는 범위 초과 (같은 부호끼리 더했는데 부호가 바뀜)
- **INC/DEC는 CF를 바꾸지 않음**
- NEG는 0이 아닌 값에 대해 항상 CF = 1

## 손코딩 필수 패턴

**배열 순회**
```asm
mov esi,0
mov ecx,LENGTHOF array
L1: mov eax,array[esi]
    add esi,TYPE array
    loop L1
```

**두 포인터 마주 보기 (뒤집기)**
```asm
mov esi,OFFSET array
mov edi,OFFSET array + SIZEOF array - TYPE array
mov ecx,LENGTHOF array / 2
```

**메모리 → 메모리 (레지스터 경유)**
```asm
mov al,source[esi]
mov target[esi],al
```
